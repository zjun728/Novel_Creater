# 项目概览与审稿整章调整落实记录

日期：2026-09-20。授权：用户明确要求“开始吧。审稿整章调整按照你的规划来”。本批在保护既有工作区修改的前提下，补概览主布局与审稿整章调整的最小后端能力，不扩展自动故事块或跨卷规划。

## 实现

- 项目概览按 Figma 14:36 调整为紧凑标题、当前进度与继续创作、当前故事块、最近定稿；旧模块与详细统计收进默认折叠的详情。复用 preparation、planning、manuscript 接口，不根据最近定稿章号自行推算下一章。跨项目迟到响应、外项目目标、状态不可用均不能产生错误继续入口。
- 审稿依据 Figma 57:120 的“基于审稿意见调整”及 68:620 的旧稿保留规则，增加独立确认流程。先保存旧稿，再启动调整；保存失败、未保存审稿修正、正文或审稿变化、归档、定稿、忙碌与结果不明状态保持保护。
- 复用 draft-operations 任务、流式输出、幂等、取消和恢复机制，增加独立 `reviewReference` 参数。`operationType: generate_new` 仍是现有整章任务载体，服务端有明确的审稿调整分支；没有把意见拼入 2000 字临时要求，也没有新增任务表或迁移。
- 引用绑定审查 ID、候选 ID / 哈希、变更集修订 / 哈希、报告哈希。服务端读取并验证持久化完整报告及原稿，核对当前工作稿、规划、小纲、Canon。启动与写回均验证；停止生成采用部分稿前也验证，漂移时保留原稿并使任务过期。
- 成功写回与旧审稿失效在同一事务中完成；即使返回正文相同，也要求重新审稿。停止并采用部分稿同样使旧审稿失效。失败保持旧稿、已有候选和原审查记录。

## 意见能力映射及边界

本批“有效意见”指当前、完整完成、仍与候选及创作依据匹配的服务端质量报告：完整传递 findings 与 deterministicBlocks，不截断、不仅取第一项。变更集修正是事实提取结果，修订 / 哈希用作版本保护，**不会把作者修正的事实变更集直接当作正文改写命令**。审稿意见不能覆盖已确认小纲或既定事实。

当前报告没有逐条“忽略”状态，本批没有新增忽略建议的持久化契约；不能宣称原型审稿结果弹窗、严重程度分类和逐条忽略已全部完成。现有审稿工具区保留，本批完成其中的整章调整入口和传递链。

自动生成首个故事块、阶段 / 任务，以及后续故事块 / 跨卷自动承接仍待决。其他页面差异继续参照逐页复核清单。此记录不代表整套前端按原型验收完成。
