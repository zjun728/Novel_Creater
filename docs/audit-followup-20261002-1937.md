## CORS 行为与配置

应用创建时读取环境变量 `CORS_ALLOWED_ORIGINS`，不读取请求 Origin 来扩大授权：

| 配置 | 结果 |
| --- | --- |
| 未设置 | 允许 `http://localhost:5173` 与 `http://127.0.0.1:5173` |
| `http://127.0.0.1:15273` | 仅允许该验收来源，替换默认列表 |
| 多个来源以逗号分隔 | 精确匹配、去重；只接受明确 HTTP(S) 回环来源 `localhost`、`127.0.0.1`、`::1` |
| 空字符串 | 不授予任何跨源读取许可；同源部署正常工作 |
| 任意端口、通配符、外部／伪装域名、null、路径、用户信息、查询或片段等非法配置 | 启动失败，固定错误信息不回显配置值 |

例如，隔离前端使用 15273 时，在**该隔离后端进程**启动前设置：

```powershell
$env:CORS_ALLOWED_ORIGINS = 'http://127.0.0.1:15273'
python -m uvicorn backend.main:app --host 127.0.0.1 --port 18100
```

修改环境变量后需重启对应后端；不写入正式私有配置。默认开发前端保持 5173；其他端口须显式配置。同源部署不需要增加外部站点来源。十九个现有动态端口 runner 已配置实际 `viteUrl`，milestone1／topic-center-live 的默认 5173 和已有同源打包调用保持兼容。

未允许的简单 GET 仍可能收到 HTTP 200，但没有 `Access-Control-Allow-Origin`，浏览器不能跨源读取；预检失败。**CORS 不是认证，也不提供本机进程完全隔离。** 此前服务默认绑定回环地址，本批没有公网暴露或已有泄漏证据。没有引入会话令牌或修改客户端协议。

最终相关后端检查 **216 通过、11 跳过**，其中新增来源边界回归 32 项均通过。旧正则的未配置 localhost／127.0.0.1 两项先失败，失败日志保留。隔离 runner 相关 Node 契约检查 **305 通过**；最后的 Phase3 环境覆盖顺序调整重跑其 73 项，替换原重叠证据，不累计为 378 项。

最终真实 Chromium＋HTTP 核对 **9 项通过**：显式来源的 GET 与实际预检可读取，未配置来源的 GET 与预检被浏览器阻止，同源读取正常，外部／伪装／null 和未配置端口没有跨源读取许可。使用实际生产 app、CORS 中间件和项目 GET 路由，项目列表服务替换为无数据库列表，关闭 lifespan；这只证明访问边界，不是正式库功能或认证验收。
