## 本批改动

- 审稿提示先核对事件时间、数量、原件/抄件、保管与交接，再核对历史；仅输出有实际问题和修改动作的意见，不把“无需修改”等肯定评价填成 optional。真实矛盾仍要求 required。
- 事实提取区分当场行动、未来安排、人物声称和已证实事实；任务正文与完成证据须同时满足。重点区分看见签押名单与查明替换手法、批注盖印与已知批注内容，禁止靠小纲目标补成已发生结果。
- 网关只合并同一事实、同一实体、类型、字段、值、有效章号和证据位置完全相同的 Canon 记录。不同 ID、置信度和解释不构成新事实；不同证据、状态与发生时间保留。不做语义猜测式删除，不自动修正作者数据，不更改旧报告。重复 ID 仍先按原契约拒绝。
- 完整章节增加总篇幅及分场预算，按已确认小纲容量优先、创作合同其次，作者明确临时字数要求仍优先。局部修改不套整章预算，不自动截断正文，不改变模型和持久配置。
- JSON 请求与正文流式请求增加安全失败日志：随机请求标识、固定阶段、HTTP 状态；流式请求另记已接收字节数。覆盖 HTTP、超时、JSON 内容、SSE 帧、缺少终止和清理等阶段。日志不记录提示词、正文、URL、密钥或远端异常文本，公开错误契约与取消行为不变。这是服务端诊断日志，不是新增用户界面错误详情，也不是对过去失败根因的追溯证明。
