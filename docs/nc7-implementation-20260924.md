## 实现与规则

- `GET /api/projects/{project_id}/planning/continuation` 只读取权威状态，不创建工作稿、不生成、不改变正文进度。前端检查使用独立状态，不刷新或替换编辑中的 planning store。
- 故事规划的分卷、情节线、故事块阅读页共用顶部“后续安排”；定稿阅读页底部增加“检查后续安排”快捷入口。目录点击继续只读，编辑仍由作者主动进入。
- 同卷已有后续块优先复用，不能跳过它直接跨卷。没有同卷后续块时，明确提供“继续本卷”与“准备下一卷”两种动作，由作者选择；系统不把“未预排下一块”等同于“本卷完结”。
- 已有完整安排：选择已有故事块、保存工作稿、展示对比，不调用模型，也不要求模型就绪。已有缺项：`fill_next_block` / `fill_next_volume` 只填空白字段、空阶段或任务列表；不删除、不重排、不改写已有内容。下一卷已有但无首块时，只补它的首块。
- 已实施节点不允许被补全改写；填充结果、生成回写及确认沿用并发和进度保护。手动切换活动块也在确认时重新检查，不能绕过同步、写作中、未完成或跳过已有安排的限制。更换创作基础后重新规划不误用此承接限制。
- 已有工作稿、未保存修改、生成待核对、同步未完成均给出相应阻塞说明。模型失败保留原稿，不自动打开旧稿的采用弹窗。
- JSON 提示明确声明返回格式；模型遗漏新节点临时标识时由服务端分配。已有目标的不可变标识仅在遗漏时从权威目标补回，提供冲突标识或修改已有正文仍拒绝。
