# 自动规划、承接与故事块调整能力实施

> 2026-09-26 更新：已有后续安排的缺项补全与完整复用已由 NC7 落地，卷级真实浏览器/模型链路验收已补齐。详见 [NC7 最终验收](nc7-final-acceptance-20260926.md)；下文为原批次实施与验收记录。

用户于 2026-09-22 授权继续剩余能力缺口。本批扩展已有规划生成链，不重构正文或定稿链。

- 首次准备：基于已确认创作基础生成分卷、情节线及第一个故事块（含阶段、任务），仅写工作稿，作者核对确认后进入权威下一步。
- 下一故事块：读取已定稿进度，当前故事块完成后准备同卷下一安排；已有后续块优先复用。
- 下一卷：当前卷没有尚待完成的后续块时准备下一卷首块；保留已存在的安排、身份及历史。
- 生成与采用均核对权威进度；生成期间进度变化时丢弃过期结果。正文、Canon 与投影不由规划生成修改。
- 原有分卷／情节线调整保持兼容。同步异常仍为状态重查，服务端主动修复不在此批承诺内。
- 当前故事块 AI 调整：作者填写具体要求，只修改当前块的未来安排，保留已推进任务和已完成阶段；对比确认后生成新修订，不推进正文进度。

验证：输出约束、前置条件、幂等模式冲突、进度漂移及工作稿确认保护的回归测试；前端入口和参数传递；构建及隔离数据库验证。模拟与真实模型证据分别记录。

## 已实现的契约

规划生成接口增加可选 `generationMode`：`volumes_plots`（历史默认）、`initial`、`next_block`、`next_volume`、`revise_block`。不新增表或迁移；继续使用原工作稿、生成租约、幂等键、CAS、修订确认与下一步查询。

- 默认模式仍仅调整分卷和情节线；未传新参数时保留旧请求指纹和旧 manifest 序列化。
- 首次模式要求尚无已确认规划、故事块和定稿正文；生成的首块必须属于第一卷，每个阶段有场景任务。
- 承接要求正文与投影同步、没有正在写作的章节、当前故事块已完成（或任务均完成），且工作稿与已确认安排一致。已有待确认修改先处理，不覆盖。
- 同卷承接优先使用已有后续块；跨卷不能跳过当前卷的后续安排。没有对应安排时生成新增内容。模型仅返回 `nextVolume` / `nextStoryBlock`，服务端合并原内容并再次验证，不让模型重抄历史。
- 生成冻结进度，写回前重查；作者确认前再次检查。其后进行分卷／情节线生成，也不能抹掉该工作稿原有的进度依据。
- 确认后继续调用 preparation 的权威下一步，不写死章节号。对比窗口已修正：单独切换活动块不再把原块内容误标为修改。
- `revise_block` 要求具体作者要求、当前块尚未完成、没有正在写作的章节，且工作稿与确认稿一致。模型仅返回当前块，其他块和分卷／情节线由服务端原样保留；已有进度的任务和完成阶段必须逐值保持。当前块身份、顺序、所属卷不变；新增或调整的未来内容形成新规划修订。

- 最终后端相关整组 276 / 276，覆盖四种新模式、旧模式兼容、输出约束、受保护节点、幂等与状态漂移。`output/planning-capability-backend-final.txt`。
- 最终前端控制器、存储、真实组件与对比回归共 106 / 106。`output/planning-capability-frontend-final.txt`。
- 隔离 MySQL 3 / 3：首次生成／确认／当前块 AI 调整确认、正文进度漂移后禁止确认（包括后续普通生成不能丢失保护），以及首次规划→真实定稿事务→下一块→第二次定稿事务→下一卷。数据库 created=3、cleaned=3、remaining=0。模型和审稿在该组使用受控数据。`output/planning-capability-mysql-final.txt`。
- 真实模型 `deepseek-v4-flash` 首次生成 3 卷、5 条情节线、1 个故事块、3 个阶段、9 个任务；浏览器核对并确认。使用独立隔离库；夹具旧 Bible policy 导致首次权威跳转返回基础页，已定位为夹具差异，不冒充首次直达工作台验收。`output/planning-live-20260922/`。
- 另一隔离库的同卷承接由浏览器点击→真实模型→真实工作稿→浏览器确认完成，权威跳转第 2 章。跨卷最终生成使用同一正式生成服务直接调用真实模型，浏览器重新读取、对比与确认后进入第 3 章。跨卷这次最终成功不记作按钮发起的完整端到端验收。`output/planning-continuation-final-20260922/next-volume-generation.json`。
- 承接验收的正文与审稿是明确标注的受控夹具，小纲、章节会话、候选稿、定稿、Canon／投影为真实服务事务；不代表 AI 已完成连续两章正文创作与审稿。
- SQL 最终核对 R1/R2/R3：旧故事块、旧分卷、情节线逐值不变；当前块属于新增第二卷；两章定稿与 Canon/Projection=2 保持一致，原正式项目会话未变。`output/planning-continuation-final-20260922/consistency-evidence.json`。
- 当前块调整通过真实生成服务直接调用模型，新增一项“记录县志异动代价”任务，浏览器对比／确认后仍进入第 3 章。SQL R4 核对当前块 ID、不相关规划和原任务逐值保持，仅新增 1 个任务，Canon/Projection 仍为 2。`block-adjustment-generation.json`、`block-adjustment-evidence.json`；这也不是按钮发起的完整端到端生成验收。
- 已目视核对新增内容对比和第二卷阅读页；1440×900、1366×768 无横向溢出。截图 `output/playwright/planning-next-block-confirm-final.png`、`planning-next-volume-confirm.png`、`planning-block-adjustment-confirm.png`、`planning-final-reader-{1440,1366}.png`。最终构建通过，9.90 秒。

真实模型试验发现并修复：原样返回旧块、JSON 模式缺少明确 JSON 指令、跨卷错误沿用原卷。失败均未加载工作稿；最终通过明确单次目标、非空输出约束与服务端合并保留历史解决，不降低校验。

## 保留边界

本批完成首次完整规划、两种进度承接及当前故事块 AI 定向调整。AI 调整范围是当前块尚未实施的未来安排，不是任意历史块改写；已有表单仍可用于作者编排。已预排但内容不完整的后续块仍需作者补齐。服务端主动同步修复、稿件排序、创作基础回看布局等后置项不由本批覆盖，也不宣称全部原型已逐像素完成。

所有业务写入仅发生在有名称校验的临时数据库，无正式库迁移／小说写入，未提交或推送。自有运行时的停止与数据库清理由各测试目录的 `stopped.json`、`database-cleaned.json` 记录。

本批已安全停止：浏览器 nc-planning 关闭，三个浏览器验收库均已清理，18000／18001／15173／15174 无监听；回执 `output/planning-capability-stop.json`。既有工作区修改保留。
