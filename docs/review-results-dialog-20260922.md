# 审稿结果弹窗与意见能力映射

后续进展：分级、持久化忽略与有效意见过滤已在下一批落实，见 [实施与验收记录](review-finding-decisions-20260922.md)。以下保留本批原始边界。

本批依据用户“开始吧”授权，落实审稿结果弹窗、现有意见分类，并完成逐条忽略的能力映射。实时读取 Figma `MlGD3vaBlodaO7PM3HgipO` 的 `57:120` 设计上下文及截图。保留既有修改，未扩展后端或修改数据库。

## 本批实现

- 新增独立 `ReviewResultsDialog.vue`，采用原型 860×680 弹窗、暖白背景、浅色意见卡片和棕红主操作。正文区域独立滚动，底部操作常驻，小屏按可用空间收缩。
- 审查完成后自动打开，侧栏提供“查看本章审查结果”；原质量建议长列表改为数量摘要，事实、进度与规划变更继续使用现有确认表单。
- 展示真实章号、审查标题、确定性阻断数量和质量建议数量。质量建议按现有十个 dimension 分类，不根据意见文字猜测严重程度。未知维度归入“其他建议”，不丢弃条目。
- 显示冻结候选稿中的证据；长原文超过 160 个 Unicode 字符时默认摘要显示，可以展开完整原文。建议内容不截断，也不改变发往后端的审稿引用。
- “定位原文并修改”关闭弹窗并复用原定位事件；“基于审稿意见调整”关闭弹窗并进入已有保存旧稿确认流程。未保存修正、忙碌、正文过期、审查失效和已定稿时保护相应动作。
- “核对定稿变更”关闭弹窗并滚动、聚焦已有变更集。没有在弹窗里增加绕过事实确认的直接定稿命令。存在确定性阻断时禁用该入口。

## 原型与现有契约的差距

| 原型行为 | 当前能力 | 本批决定 |
| --- | --- | --- |
| 必须调整 / 建议调整 / 可忽略三级 | `QualityFinding` 只有 id、dimension、reason、suggestedAction、evidence；无 severity。提示词明确质量意见仅作建议，不决定定稿。`deterministicBlocks` 是服务端确定性阻断 | 阻断展示为“必须处理”，模型意见展示为质量建议并按维度分类；不把连续性维度直接当作强制阻断 |
| 忽略此建议 | 无逐项状态、保存接口或报告版本契约；整章调整由服务端读取完整报告 | 本批只完成能力映射，未显示不可持久化的忽略按钮，未实现忽略后的意见过滤 |
| 弹窗确认定稿 | 当前需要核对提取的事实 / 进度变更，再执行作者确认与定稿事务 | 保留原安全流程，通过“核对定稿变更”衔接，不能声称已完全复刻原型底部动作 |

参考代码：`backend/domain/finalization.py` 的 `QualityFinding` / `QualityReportPayload`；`backend/prompts/finalization.py` 的 advisory 约束；`frontend/src/utils/reviewReference.js`；`backend/services/draft_operations.py` 的引用与版本校验。

逐条忽略若进入下一实施批次，最小契约应包括：

1. 明确哪些质量意见允许忽略，以及严重程度由谁提供。确定性阻断不能通过忽略消除。旧报告无分级字段时不能默认视为可忽略。
2. 将作者处理状态独立绑定到项目、审查 ID、报告哈希和 finding ID，采用版本比较保存，支持恢复采用；不改写原模型报告内容或伪造报告哈希。
3. 前端读取权威处理状态；刷新后保留，保存失败维持原状态，跨项目 / 新审查不继承旧忽略集合。
4. 整章调整由服务端筛选未忽略意见，同时绑定处理状态修订；启动与写回再次校验，避免生成中处理状态变化后采用旧意见。
5. 审稿页面数量、调整确认及后端提示词使用同一有效意见集合；全部忽略时禁止空意见调整。定稿阻断仍由服务端裁决，不能只改按钮是否禁用。

这些是能力映射与下一批实现要求，不是本批已完成后端能力。
