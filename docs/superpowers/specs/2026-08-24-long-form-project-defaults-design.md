# 长篇项目默认规模设计

日期：2026-08-24
状态：已确认，待实施

## 目标

让新建项目默认符合平台的超长篇定位：目标总字数为 2,400,000 字，预计章节数为 720 章。

本次只修改新项目默认值。现有项目保持原值，用户显式提交的目标值继续优先，不增加项目模板、档位选择或迁移脚本。

## 方案

后端 `CreateProject` 继续作为新项目默认值的权威来源，将缺省的 `target_words` 和 `target_chapters` 分别改为 `2_400_000` 和 `720`。创建接口没有显式传入这两个字段时，响应和持久化命令都采用新默认值；显式传值时行为不变。

前端创作合同的临时容量计算只在既没有合同草稿、也没有项目目标数据时使用兜底值。该兜底同步为 2,400,000 字，并继续按每章约 3,000 字推导 800 章；正常的新项目会直接使用后端返回的 720 章，因此不会覆盖项目权威目标。

不抽取跨前后端共享配置。当前只有两个既有默认位置，增加配置协议会扩大维护范围，超出本次需要。

## 数据与兼容性

- 不更新数据库中的任何现有项目。
- 不改变 API 字段、数据库结构或校验上限。
- 不强制所有项目至少 2,000,000 字；用户显式创建短项目仍然合法。
- 不改变单章目标、上下文窗口、输出 token 或 Provider 配置。

## 测试与验收

实施遵循测试先行：

1. 先把后端命令、创建服务和创建接口的默认值断言更新为 2,400,000 字、720 章，确认旧实现下测试失败。
2. 增加前端合同容量兜底的回归断言，确认缺少项目数据时使用长篇规模。
3. 完成最小实现后运行相关测试、全量测试和前端生产构建。
4. 确认 Git 差异不包含数据库、Provider 配置或现有项目数据变更。

## 非目标

- 不迁移或重写“典镇山河”等已有项目。
- 不新增长篇/短篇预设选择器。
- 不改造新建项目界面。
- 不启动真实文章生成或外部网络调用。
