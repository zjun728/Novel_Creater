# Novel Creator “作品稿件”产品化设计

- 日期：2026-08-24
- 基线：`main@b2ee1b54e337ef400e79ea438cf91daf8f9ff7c9`
- 产品形态：本机单用户长篇小说创作台
- 首个真实项目：《典镇山河》；已定稿第 1–3 章；当前权威章节为第 4 章
- 状态：设计已获用户逐节批准；独立反方规格审核 `Blocking/Major/Minor = 0/0/0`；待用户书面复核

## 1. 决策摘要

采用“稿件优先”的垂直切片。先建立稳定的“作品稿件”模块，让作者能从项目导航重新找到、阅读、下载已定稿正文，并从稿件回到当前创作任务；随后再逐段产品化其他创作阶段。

本切片不是视觉换皮。它闭合以下真实任务：

1. 作者从项目侧栏进入作品目录；
2. 按卷查看全部已定稿章节及真实章名；
3. 站内阅读经过完整性校验的单章定稿；
4. 在同章回看定稿采用的小纲；
5. 使用上一篇、下一篇、目录和浏览器历史稳定导航；
6. 从稿件页继续服务端当前权威章节；
7. 下载单章、分卷或整本定稿；
8. 项目归档后仍可只读阅读和下载。

旧的 `/write/chapters/:chapterNumber` 只服务当前权威章节写作，不再承担历史阅读。已定稿章节不会重新开放编辑。

## 2. 背景与证据

当前项目导航只有项目概览、创作种子、创作契约、创作圣经、故事规划和模型绑定，没有稿件模块。正式路由只有当前章节写作页，没有稿件目录或只读章节阅读页。

在真实产品数据库中直接访问《典镇山河》第 1 章写作路由，页面显示“章节地址与服务端权威不一致”，只允许前往当前第 4 章。这证明写作台不能作为旧章阅读入口。

现有后端已经提供两类可复用权威能力：

- 小说下载 options 能列出一卷和三章，章名分别为《泔水醒来，三日织机赌局》《废料改机》《复验定局》；
- 第 1–3 章的小纲 history 各有一份 `session_pinned` 修订。

现有单章 TXT 下载经过完整性校验，但内容包含书名、卷名和章节分隔符，语义上是文件交付，不适合作为站内阅读正文。前端不得通过字符串裁剪下载文件来构造阅读页。

## 3. 目标与非目标

### 3.1 目标

- 建立作者可理解、可发现、可深链接的作品稿件信息架构；
- 保持定稿正文、定稿小纲和当前写作章节之间的权威边界；
- 让每个页面只有一个当前主动作，并提供明确离开路径；
- 默认界面只使用作者语言，内部标识只进入可展开诊断；
- 保证目录和只读阅读在窄屏、200% 缩放和键盘下可用；
- 复用既有完整性校验和下载能力，不复制一套弱化校验；
- 不调用真实 Provider，不改变定稿、不重新生成章名或正文。

### 3.2 非目标

- 不允许编辑、替换、回滚或重开已定稿章节；
- 不实现章节搜索、批注、书签、阅读进度同步或排版主题市场；
- 不实现通用修订历史中心、版本 diff 或全文统计仪表盘；
- 不重构种子、契约、圣经、规划或写作台的完整视觉体系；
- 不在本切片完成 Canon、人物、伏笔等其他内容管理模块；
- 不新增后台任务、通用 workflow、Provider 调用或数据库迁移框架；
- 不把下载附件解析成正文，也不从正文首行猜测章名。

## 4. 信息架构与路由

新增两个稳定路由：

```text
/projects/:projectId/manuscript
/projects/:projectId/manuscript/chapters/:chapterNumber
```

第一个路由是作品目录，第二个路由是已定稿章节阅读。`chapterNumber` 必须是正整数；服务端必须验证该章属于该项目且已经定稿。

项目侧栏在“故事规划”之后、“模型绑定”之前增加：

```text
稿  作品稿件
```

活动项目和归档项目都显示该模块。写作台、作品目录和章节阅读都保持当前项目上下文；侧栏在稿件两个路由上统一选中“作品稿件”。顶栏标题分别为“作品稿件”和仅由路由即可稳定得出的“第 N 章定稿”；权威章名由阅读页 `h1` 展示，不把异步正文数据发布到全局 shell，也不发起重复标题请求。

项目概览移除完整下载控件，改为一条稿件摘要入口，例如“作品稿件 · 已定稿 3 章”。项目备份仍留在现有位置。本切片不新增第二套稿件入口或重复下载面板。

## 5. 作品目录

作品目录采用连续书目，不做卡片式仪表盘。

### 5.1 页头

页头展示：

- 作品名；
- 已定稿章数；
- 已定稿总字数；
- 当前创作位置，例如“已定稿 3 章，下一章为第 4 章”。

活动项目的唯一主动作来自既有 project preparation 请求及一份共享的前端动作文案 mapper：

- 当前权威章节具备写作会话或工作稿：`继续创作第 N 章`；
- 当前权威章节尚缺小纲：`准备第 N 章小纲`；
- 其他安全状态：使用 preparation 的 `nextAction`、`targetPath` 和 `authoritativeChapterNumber` 映射为作者可行动目标；
- 无法得到安全目标：显示“重新读取创作状态”，不猜测路由。

稿件目录 API 不复制 preparation DTO，也不返回本地化 `label`。稿件内容与 preparation 分别加载；前者成功、后者失败时仍正常显示目录，只把创作动作变成可重试的 `unavailable` 状态。归档状态不请求或不采用创作动作。

归档项目不显示创作动作，只显示“已归档 · 只读”。

整本和分卷下载收进页头的次级“下载”菜单；菜单只展示 options 声明可用的范围和格式。

### 5.2 目录正文

章节按第 6.3 节的唯一全局顺序排列，并按连续卷边界分组。每个章节行展示：

- 第 N 章；
- 权威章名；
- 字数；
- 定稿时间；
- 只读状态。

章节阅读链接和单章下载按钮是同一 grid row 中的兄弟元素，禁止用链接包裹按钮或嵌套其他交互控件。阅读链接占据主要点击区域；下载按钮是次级动作，并在需要选择格式时打开小菜单。

无定稿章节时显示单一空状态：“还没有已定稿章节”，并根据当前 preparation 提供安全的创作入口。空状态不显示禁用下载控件。

## 6. 定稿阅读

### 6.1 页面结构

阅读页采用单栏电子稿纸结构：

1. 顶部返回作品目录；
2. 展示卷名、第 N 章、章名、字数、定稿时间；
3. 提供“正文 / 本章小纲”二项切换；
4. 默认显示纯正文；
5. 页面底部提供上一篇、目录、下一篇；
6. 活动项目页头提供当前创作动作，归档项目不提供。

正文保持适合长时间阅读的行长、字号和行距，不在正文两侧增加常驻诊断栏、版本栏或工具栏。

“正文 / 本章小纲”选择写入查询参数：

```text
?view=text
?view=outline
```

缺失或无效参数统一回到 `text`，不报错。刷新、浏览器前进后退和分享深链接应恢复同一视图。只改变 `view` 不重新请求章节、不增加请求世代、不把焦点移动到 `h1`，也不重置正文或自定义主滚动容器的位置；只有项目 ID 或章号变化才进入新的章节请求世代。

### 6.2 本章小纲

小纲来自 `final_chapters.chapter_outline_revision_id/revision/hash` 精确钉住的 Outline，由专用章节只读 API 与正文一起返回。前端不再从 history 展示状态中查找 `session_pinned`，因此项目归档不会改变本章采用的小纲。正常作者界面只展示：

- 本章目标；
- 预计人物；
- 延续项；
- 计划任务；
- 场景；
- 禁止提前发生事项。

卷、故事块、阶段、场景任务的 ID、revision、hash、Canon/Projection 基线和原始状态码不进入主界面。若诊断确有必要，只能放进默认折叠的“高级诊断”，并继续禁止正文、秘密、DSN 或 Provider 原文进入通用日志。

每个合法定稿都必须精确钉住一份小纲。钉住小纲缺失、hash 不符或无法解析均属于章节完整性失败；不得从 history 猜选替代修订，也不得只显示正文掩盖定稿权威链损坏。

### 6.3 章节导航

唯一 canonical reading order 是实际 `final_chapters.chapter_num` 全局升序；目录和上一篇/下一篇必须共用这一扁平序列，不使用当前权威章节号推断。章号缺口允许存在，导航直接跳到下一条实际定稿。沿全局章序遍历时，卷序必须单调不下降，同一卷必须连续且卷 ID、卷序、卷名一致；违反这些结构关系时目录 fail closed。首个实际定稿不显示上一篇，末个实际定稿不显示下一篇，跨卷导航仍按全局章序继续。

“继续创作”始终使用 preparation 返回的当前目标，不把旧章号传给写作台。阅读页不出现“编辑本章”“重新打开会话”或任何会改变定稿的动作。

## 7. 定稿后的任务转场

定稿成功后不自动跳页，避免打断作者核对结果。`FinalizationPanel` 重新读取 project preparation，并通过与概览、目录、阅读页共用的动作文案 mapper 提供两个层级清楚的动作：

- 主动作：使用重新读取后的 preparation 映射结果，例如 `准备第 N 章小纲` 或 `进入第 N 章写作`；
- 次动作：`查看本章定稿`，进入新阅读路由。

如果 preparation 尚未稳定或读取失败，主动作改为“重新读取创作状态”，不得自行计算下一章或固定写成“准备下一章”。次动作只在刚定稿章节可以被只读接口重新读取并通过完整性校验后出现。

作品目录和阅读页的当前创作动作遵守同一规则。这样形成：

```text
写作与定稿 → 查看本章定稿 / 准备下一章 → 作品目录可持续回看
```

其他阶段的契约→圣经→规划→小纲转场属于下一垂直切片，不在本规格顺带修改。

## 8. 后端只读查询契约

新增只读 API，不复用附件下载响应作为阅读数据：

```text
GET /api/projects/{project_id}/manuscript
GET /api/projects/{project_id}/manuscript/chapters/{chapter_number}
```

### 8.1 目录响应

```json
{
  "projectId": "project-id",
  "title": "典镇山河",
  "lifecycle": "active",
  "summary": {
    "finalChapterCount": 3,
    "totalScalarCount": 10764
  },
  "volumes": [
    {
      "id": "volume-id",
      "order": 1,
      "title": "匠户破锁",
      "chapters": [
        {
          "number": 1,
          "title": "泔水醒来，三日织机赌局",
          "scalarCount": 3412,
          "finalizedAt": "2026-08-24T00:00:00Z"
        }
      ]
    }
  ]
}
```

示例数值仅说明字段形状，不是测试固定值。正式响应必须拒绝未知查询参数，并按 canonical reading order 确定性排序。当前创作动作不属于此响应；前端复用既有 preparation 请求和共享 mapper。

目录查询是轻量元数据查询：不得把所有 `final_chapters.content` 传到应用层，也不得为了显示目录重建整本下载快照。它仍须验证项目、定稿记录、ChapterSession、钉住的 Outline/Planning 以及卷章归属一致；结构关系损坏时目录 fail closed。`scalarCount` 可以由数据库对 `utf8mb4` 正文执行与 Unicode scalar 语义一致的字符计数，再由服务层校验为非负整数；`totalScalarCount` 是章节计数的确定性求和。目录能列出章节不代表该章已经完成正文 SHA-256 验证，正文仍必须在打开章节或下载时单独 fail closed。某一章只有正文内容或正文 hash 损坏时，目录仍显示该章元数据，但打开和下载必须拒绝正文，不能让作者误以为整本书没有章节。

### 8.2 章节响应

```json
{
  "projectId": "project-id",
  "projectTitle": "典镇山河",
  "lifecycle": "active",
  "volume": {
    "id": "volume-id",
    "order": 1,
    "title": "匠户破锁"
  },
  "chapter": {
    "number": 1,
    "title": "泔水醒来，三日织机赌局",
    "content": "后脑勺像被人……",
    "scalarCount": 3412,
    "finalizedAt": "2026-08-24T00:00:00Z"
  },
  "outline": {
    "chapterGoal": "本章目标",
    "expectedCharacters": ["人物甲"],
    "continuation": ["延续项"],
    "plannedTasks": ["计划任务"],
    "scenes": ["场景"],
    "forbiddenEarlyEvents": ["禁止提前发生事项"]
  },
  "navigation": {
    "previousChapterNumber": null,
    "nextChapterNumber": 2
  }
}
```

章节正文必须经过与小说下载相同的钉住关系、Planning/Outline 内容 hash 和最终正文 SHA-256 完整性校验。实现应抽取或复用既有校验服务，不能复制一份较弱逻辑。响应使用 `Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`。

章节查询只读取并验证目标章及其精确钉住的 Outline/Planning，不得先载入全部已定稿正文。`outline` 是已验证 Outline 的作者字段投影，不返回 ID、revision、hash 或 basis。上一篇和下一篇来自同项目的轻量目录元数据；邻章无需在当前请求中载入正文。共享复用的边界是现有完整性校验规则和领域 helper，不要求调用当前会重建整本快照的下载 service 方法。

`scalarCount` 使用项目现有 Unicode scalar 计数语义；前端统一显示为“字数”，不另造不一致的 JavaScript `length` 统计。`finalizedAt` 来自权威定稿记录的持久化整数时间，并按项目现有时钟单位在服务端转换为 UTC RFC 3339 字符串；不得使用客户端时间或猜测时间单位。

### 8.3 下载完整性范围

阅读与下载按请求选择范围校验，不让范围外的正文损坏阻断安全内容：

- 目录：验证结构关系，不读取正文；正文/hash 损坏仍列元数据；
- 阅读第 N 章：只验证第 N 章的完整钉住链和正文 SHA-256；
- 下载单章：只验证所选章；
- 下载分卷：验证该卷全部所选章，任一失败则整个分卷下载失败；
- 下载整本：验证全部章，任一失败则整本下载失败。

这要求下载选择器先确定请求范围，再对所选章节执行正文校验；不得继续让范围外损坏导致安全的单章下载失败。结构关系损坏仍按无法安全确定选择范围处理并 fail closed。

### 8.4 公开错误契约

两条 API 使用现有 `PublicDomainError` 响应形状，固定矩阵如下：

| HTTP | code | 含义 | 前端作者状态 |
| --- | --- | --- | --- |
| 404 | `ManuscriptProjectNotFound` | 项目不存在 | 返回项目库 |
| 404 | `FinalChapterNotFound` | 章号不存在或尚未定稿 | 返回作品目录，可另行显示安全创作动作 |
| 422 | `ManuscriptRequestInvalid` | 非正整数章号或额外查询字段 | 显示无效章节地址并返回目录 |
| 500 | `ManuscriptIntegrityFailure` | 钉住关系、结构、内容 hash 或正文 hash 损坏 | 拒绝正文，提供重新读取和关联编号 |
| 503 | `ManuscriptTemporarilyUnavailable` | 数据库或服务暂时不可用 | 保留已有安全内容并局部重试 |

公开 `message` 使用固定英文安全摘要以遵循现有后端约定；前端只按 `code` 映射固定中文作者文案，不直接渲染服务端 message。未知错误统一进入临时不可用状态。响应不得包含内部 ID、hash、字段路径、SQL、正文或原始异常。

## 10. 状态与错误处理

### 10.1 页面状态

- 加载：保持目录或稿纸骨架，使用 `aria-busy`；
- 空目录：说明尚无定稿并提供当前安全创作动作；
- 项目不存在：返回项目库；
- 章节不存在或尚未定稿：说明“不属于作品稿件”，并提供目录和当前安全创作动作；
- 完整性失败：拒绝正文阅读和下载，不回退到工作稿或候选稿；
- 临时失败：保留已有安全内容，提供局部重试；
- 归档项目：明确只读，隐藏创作动作。

### 10.2 公开错误

API 和 controller 将内部错误映射为固定作者文案。关联编号可在默认折叠的诊断中显示。普通页面不得原样渲染数据库错误、原始异常、字段路径、ID、hash、正文或 Provider 内容。

稿件内容与 preparation 状态各自独立：

- 目录失败不伪造空书；
- 章节完整性失败时正文和同一钉住链的小纲都不展示；
- 当前创作状态失败不影响阅读，只隐藏不安全 CTA 并允许重新读取。

## 11. 响应式与可访问性

本切片只做稿件阅读必需的应用壳修复，不重画现有桌面导航。

- 在应用壳最前增加可见于焦点的“跳到主内容”；
- 主内容提供稳定目标和程序化可聚焦页标题；
- 760px 以下不保留固定 72px 导航轨，改为顶栏按钮控制的导航抽屉；
- 抽屉使用 `role="dialog"`、`aria-modal="true"` 和可见标题，包含可见关闭按钮；打开后背景 `inert` 且锁定背景滚动，焦点进入第一个可操作项，Tab 不离开抽屉，Escape 或关闭按钮关闭，关闭后焦点回到菜单按钮；
- 桌面侧栏选中状态继续使用 `aria-current="page"`；
- 章节目录行、视图切换和上一篇/下一篇均可键盘操作；
- 触控目标不小于 44×44 CSS px；
- 整个应用壳、目录和正文在 390px 与 200% 浏览器缩放下都不横向滚动；
- 正文行宽约 38–44 个中文字符，使用相对字号和不小于 1.75 的行高；
- 遵守 `prefers-reduced-motion`；
- 项目 ID 或章号通过新导航变化后，焦点移动到页面 `h1` 并把自定义主滚动容器置顶；`view` query 变化不跳焦点、不改滚动；浏览器前进/返回按 history entry 保存并恢复自定义主滚动容器的 `scrollTop` 和仍存在的焦点目标。

桌面 1280px 以上仍使用现有侧栏。761–1119px 保留现有紧凑桌面模式，但必须隐藏模块文字或提供可理解标签，不能出现逐字挤压的竖排文字。

可重复浏览器矩阵固定为：

- 1440×900，浏览器缩放 100%，完整桌面侧栏；
- 1280×800，从浏览器缩放 100% 调至 200%，验收整个壳层、目录、阅读和导航抽屉；
- 390×844，浏览器缩放 100%，验收移动目录、阅读和抽屉；
- 760×900 与 761×900，缩放 100%，验收断点两侧行为。

200% 必须使用真实浏览器缩放，不以 `deviceScaleFactor` 或仅缩小 viewport 代替。每个矩阵断言 `scrollWidth <= clientWidth`、所有可见控制可聚焦、焦点顺序符合 DOM 语义、抽屉背景不可聚焦，并验证 Escape、可见关闭按钮和焦点归还。

## 12. 测试与验收

测试服务于真实流程，不以增加测试数量为目标。

### 12.1 确定性测试

- 路由 helper、路由 inventory 和 shell 选中状态；
- API 成功响应、公开错误矩阵、前端 code mapper、严格校验与未知字段拒绝；
- 精确钉住 Outline 的作者字段投影，活动与归档结果一致；
- 完整性校验复用及按请求范围 fail closed；
- 第 3 章正文损坏时：目录仍列元数据、第 1 章阅读和单章下载成功、第 3 章阅读和单章下载失败、包含第 3 章的分卷和整本下载失败；
- 目录 canonical order、卷连续性、总章数和 scalar 汇总；
- 上一篇/下一篇只基于实际定稿列表；
- controller 的迟到响应淘汰、query-only 切换不重取、历史滚动/焦点恢复；
- 活动/归档项目 CTA 边界；
- 定稿成功后的重新读取与两个转场；
- skip link、抽屉键盘行为和作者文案不含内部术语。

### 12.2 真实浏览器垂直场景

在一次性 MySQL 和可见浏览器中完成三组独立场景。第一组使用带三章定稿的完整 fixture：

1. 打开带三章定稿的项目；
2. 从侧栏进入作品稿件；
3. 验证真实章名和卷序；
4. 阅读第 1 章正文并查看定稿小纲；
5. 使用下一篇到第 2 章，再用浏览器返回；
6. 刷新章节深链接并恢复 `?view=outline`；
7. 从稿件页进入当前第 4 章准备或写作；
8. 验证旧章从不触发权威章节冲突；
9. 下载单章、分卷、整本，确认原下载能力未回归；
10. 归档后继续阅读正文与钉住小纲并完成下载，确认创作 CTA 消失；
11. 按第 11 节矩阵在 390px、真实 200% 缩放、760/761px 边界和键盘路径下完成目录与阅读。

第二组使用测试启动前预置为 `awaiting_author`、无需 Provider 的第 4 章 fixture，通过可见 UI 完成：

1. 确认变更并定稿第 4 章；
2. 等待重新读取 preparation；
3. 确认成功状态同时显示“查看本章定稿”和映射后的第 5 章当前创作主动作，且目标正确；
4. 使用“查看本章定稿”进入只读阅读；
5. 从阅读页使用同一 preparation mapper 的主动作进入第 5 章准备路径；
6. 再从作品目录回看第 4 章，确认定稿→回看→继续→再次回看闭环。

第三组使用测试服务启动前建立的独立损坏 fixture，不在浏览器运行中写数据库：

1. 第 3 章正文与存储 hash 不匹配；
2. 目录仍列第 1–3 章；
3. 第 1 章阅读和单章下载成功；
4. 第 3 章阅读和单章下载拒绝；
5. 包含第 3 章的分卷和整本下载拒绝；
6. 作者界面不泄露正文、hash、ID 或原始异常。

浏览器验收中的业务操作不得通过 `page.request`、浏览器 `fetch`、测试代码数据库直写、旁路接口或 DOM 状态注入绕过可见 UI。所有 fixture 只能在对应服务启动前由受控准备脚本创建；场景运行期间允许可见 UI 业务操作通过正式 API 产生正常测试数据库写入，禁止测试代码、准备脚本或旁路接口直接写库。自动门禁不调用真实 Provider、产品数据库或外部网站；第 12.3 节产品数据库 smoke 始终严格只读。

### 12.3 产品数据库只读 smoke

自动门禁通过后，在《典镇山河》产品项目上只读验证：

- 目录显示第 1–3 章及权威章名；
- 三章正文均可站内阅读；
- 三章定稿小纲均可回看；
- 第 1 章深链接不再进入权威冲突；
- 当前创作动作仍指向第 4 章；
- 不执行写作、生成、定稿、归档或其他产品数据库写入。

## 13. 分阶段交付和审核门

本规格只对应第一垂直切片。实施按以下可独立验证的阶段推进：

1. **只读领域与 API**：目录、章节正文、完整性复用、公开错误；
2. **桌面稿件产品流**：路由、侧栏、目录、阅读、小纲、下载和转场；
3. **窄屏与可访问性**：skip link、抽屉、键盘、缩放和响应式；
4. **完整验收**：focused tests、必要回归、真实浏览器、产品库只读 smoke。

每个阶段完成后均需独立代码审查和真实浏览器检查。独立审查重点验证：

- 没有把写作台重新包装成历史阅读；
- 没有通过下载文本裁剪构造正文；
- 没有打开已定稿编辑或回滚路径；
- 没有重复完整性逻辑或弱化 fail-closed；
- 没有作者导航死路；
- 没有新增无关仪表盘、版本条、权威条或诊断卡片；
- 窄屏和键盘不是仅靠单元测试自证。

完成第一切片后，再单独设计下一规格：补齐项目首页→种子→契约→圣经→规划→小纲→写作→定稿→稿件回看的阶段转场。该后续范围不得混入本实现计划。

## 14. 完成标准

本切片只有同时满足以下条件才算完成：

- 作者可从项目导航在三次交互内进入任一已定稿章节；
- 已定稿章节在推进下一章后仍可稳定阅读；
- 目录、阅读、小纲、下载、继续创作和归档只读形成闭环；
- 旧章不再进入权威章节冲突；
- 所有章名来自权威持久化数据；
- 站内正文使用专用只读 API，并复用现有完整性校验；
- 作者主界面不显示 Canon/Projection、UUID、hash、revision、原始 JSON 或内部英文状态；
- 390px、200% 缩放、键盘和减少动画验收通过；
- focused backend、frontend、browser tests 和生产构建通过；
- 风险相关完整回归通过；
- 独立规格审查、代码审查和真实浏览器审查没有未解决 Blocking/Major；
- 产品数据库 smoke 保持严格只读，真实 Provider 调用为 0；
- 根目录既有 `.review-worktrees/` 未被删除、修改或提交。
