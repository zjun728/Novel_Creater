# 创作资产页面滚动与中文显示设计

日期：2026-08-23  
状态：已确认，待实施

## 目标

修复风格模板库和经验卡页面的两个直接体验问题：

1. 鼠标位于右侧内容区时页面可以正常滚动。
2. 题材与创作阶段在所有面向用户的位置显示中文。

本次只做必要的前端修复，不调整后端数据合同，不重构页面，也不增加新的配置系统。

## 滚动根因与修复

应用将 `#app` 设为视口高度，并预期 `.product-app-shell__content` 成为右侧独立滚动容器。但 Naive UI 的根级 `NConfigProvider` 会渲染一层 `.n-config-provider` 包装元素，该元素没有继承父级高度。

实测在 900px 高视口中，右侧内容容器被内容撑到约 1929px，`clientHeight` 与 `scrollHeight` 相等，因此它自身无法滚动；同时 `overscroll-behavior: contain` 阻止滚轮继续传递给外层页面。左侧没有相同的滚动截断，所以滚轮仍会驱动页面滚动。

采用最小修复：仅让 `#app` 的直接 `.n-config-provider` 子元素继承 `100%` 高度。这样应用壳保持一屏高度，固定侧栏和顶栏不变，右侧内容重新成为唯一的纵向滚动区。不增加 JavaScript 滚轮转发。

## 中文显示

增加一个共享的前端显示映射，覆盖当前资产数据使用的题材与创作阶段稳定值。风格模板库和经验卡共同使用该映射，包括：

- 题材筛选选项；
- 阶段筛选选项；
- 卡片上的题材与阶段标签；
- 资产详情中出现的题材与阶段字段。

英文稳定值继续用于 API 查询、状态管理和数据库存储。例如 `science_fiction` 仍作为提交值，只在界面显示为“科幻”。未知的新值不报错，直接回退显示原值，避免资产包升级后界面空白。

## 测试与验收

实施遵循 TDD：

1. 先增加失败测试，证明根级 Provider 包装层必须继承应用高度。
2. 先增加失败测试，证明题材和阶段映射正确、未知值安全回退，并且两个资产页面使用中文显示函数。
3. 完成最小实现后运行相关前端单元测试、全量前端测试和构建。
4. 在真实浏览器中验证鼠标位于右侧卡片区域时滚轮会改变右侧容器的 `scrollTop`，左侧与顶栏保持固定；再检查风格模板和经验卡页面不再显示已知题材或阶段英文值。

## 非目标

- 不翻译 stable key、资产包版本或 taxonomy 版本。
- 不修改后端枚举、数据库内容或 API 响应。
- 不改动视觉布局，不引入国际化框架。
- 不处理与这两个页面无关的全站文案。
