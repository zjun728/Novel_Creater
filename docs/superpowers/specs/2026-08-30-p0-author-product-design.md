# Novel Creator P0 作者产品化与完整创作流程设计

- 日期：2026-08-30
- 架构基线：`main@0fa6a6d2bccde38c83da0021d09311c10ab8585d`
- 产品形态：本机单用户、二百万字以上长篇小说创作平台
- 状态：用户已确认总体方案；网页版 ChatGPT 5.6 Pro 审核后修订，待用户复核
- 本轮性质：产品结构与前后端边界设计，不实施代码、数据库或 Provider 调用

## 0. 最高级约束：保护本次重构成果

本轮产品化允许补齐页面、读取接口和边界清晰的新能力，但不得打乱、回退或旁路本次重构形成的创作核心。

### 0.1 必须保留的核心

- 服务端当前权威章节是唯一可写章节；
- 章节手动逐章生成、逐章定稿、逐章推进；
- WorkingDraft、候选、审核、`FinalizationChangeSet` 和原子定稿事务；
- Canon 是唯一“已经发生”的事实源；
- Current State、Memory、Arc、Plot Thread 和故事实际进度从 Canon 确定性投影；
- Planning、StoryBlock、Stage、SceneTask 与 ChapterOutline 管理未来意图；
- 定稿正文、小纲依据和其钉住的上游 revision 不可变；
- Provider、模型绑定、提示词、创作资产和上下文组装继续服从现有权威服务。

### 0.2 允许的扩展

- 新增或调整作者产品所需的 REST API；
- 新增全局选题、讨论和候选种子的边界上下文；
- 新增从全局候选种子复制到项目种子的原子、幂等交接命令；
- 新增工作台服务端分类、卷摘要、按卷章节索引和连续性只读查询；
- 可选增加“每项目最多一个 drafting ChapterSession”的数据库防御性约束，但不得替代现有服务端锁和权威判断；
- 增加作者语言 DTO、聚合查询和性能索引。

### 0.3 明确禁止

- 恢复旧 Store、旧 API、旧写作页或旧定稿链；
- 为兼容旧界面保留两套活动写入路径；
- 让前端推断权威章号、Canon revision、Planning head 或定稿状态；
- 绕过当前权威章节创建正文工作区；
- 绕过 `FinalizationChangeSet` 直接写入定稿、Canon 或规划进度；
- 分别调用模型或分别维护设定、记忆、弧光、线索和故事进度；
- 在原子定稿事务外补写 Canon、Projection、Planning 或最终章节；
- 静默修改已定稿正文、历史 Canon 或历史钉住依据；
- 在契约或圣经首次确认后增加普通修订入口；
- 用前端本地数据、测试数据或临时页面伪装正式产品能力。

若产品需求与这些约束冲突，应调整产品方案，不得以“前端体验”为理由拆改核心。

## 1. 产品目标与非目标

### 1.1 P0 目标

P0 必须让普通作者不用理解内部架构，也能在正式界面完整完成：

```text
市场参考或自由创意
→ AI 多轮选题讨论
→ 候选种子
→ 创建项目
→ 人工确认项目种子
→ 契约
→ 圣经
→ 分卷、情节线和故事块
→ 当前章小纲
→ 工作稿、候选、审核和定稿
→ 查看 Canon、状态、记忆、弧光、线索和故事进度
→ 开始下一章
```

每个正式成果都必须能回答：在哪里创建、在哪里编辑、在哪里确认、在哪里看正式版、在哪里看草稿和候选、在哪里看历史、被下游如何引用、发生错误后在哪里处理。

### 1.2 非目标

- 不做多人协作、编辑排期或多章并行生产；
- 不做无人值守批量生成章节；
- 不做复杂知识图谱、关系图、全书运营大屏或动画装饰；
- 不一次覆盖所有网站的复杂爬虫；
- 不建设独立于 Canon 的人物、记忆、弧光或伏笔 CRUD 事实库；
- 不为每个模块建设第二套版本系统；
- 不以测试页面代替作者产品页面；
- 不为暂未出现的需求预建插件市场、团队权限或云端协作架构。

## 2. 产品原则

### 2.1 一眼看懂当前页面

页面首屏必须明确展示当前对象、正式成果、状态和主要内容。技术诊断、原始 ID、hash、JSON 和内部 revision 默认折叠。

### 2.2 计划与事实分离

- 种子、契约、圣经、设定规划、分卷、情节线、故事块和小纲描述未来意图；
- 已定稿正文及其 Canon event 描述已发生事实；
- 当前状态、记忆、弧光、线索和实际进度是 Canon 派生视图；
- 页面必须以明确区域和标签区分“计划发生”与“已经发生”。

### 2.3 作者控制

AI 只产生讨论、草稿、候选和建议。确认种子、契约、圣经、小纲、定稿 ChangeSet 和正文定稿均由作者显式执行。

### 2.4 手动导航而非强制推进

项目侧栏始终允许用户手动切换已开放模块。契约、圣经、规划和小纲确认后不增加跨模块“继续下一步”快捷入口。写操作仍服从后端前置条件，页面应说明原因，但不替作者强制跳转。

### 2.5 不过度设计

优先使用列表、结构化详情、抽屉、弹窗和少量标签；没有明确价值时不增加仪表盘、重复入口、复杂筛选或技术状态卡。

选题中心位于项目创建之前。创作资产和设置继续保持全局作用域。

### 3.2 项目导航

├─ 创作种子

└─ 创作圣经

## 4. 核心对象所有权与状态

| 对象 | 所有者 | 权威内容 | 与下游关系 |
| --- | --- | --- | --- |
| 市场快照 | 全局选题中心 | 带来源、时间和 hash 的公开元数据 | 仅作讨论证据 |
| AI 讨论 | 全局选题中心 | 消息、附加上下文和模型结果 | 显式保存后才能产生候选 |
| 选题方向 | 全局选题中心 | 从讨论显式保存的版本化方向 | 可继续讨论或转为候选种子 |
| 全局候选种子 | 全局选题中心 | 不可变版本与当前 head | 指定版本可创建多个项目 |
| 项目种子 | 项目 | 创建项目时复制的快照及项目修订 | 人工确认后进入契约 |
| 契约 | 项目 | 首次确认前的工作草稿、AI 方案及唯一永久确认基线 | 确认后永久只读，约束圣经、规划和写作 |
| 圣经 | 项目 | 首次确认前的工作草稿、AI 方案及唯一永久确认基线 | 确认后永久只读，管理未来设定但不替代 Canon |
| Planning | 项目 | 分卷、情节线、故事块、阶段和任务 | 管未来计划 |
| ChapterOutline | 项目当前权威章 | 当前确认 revision 和历史 | 钉住章节会话输入 |
| ChapterSession | 项目当前权威章 | 唯一 drafting 会话或历史 final 会话 | 管当前章工作区 |
| FinalizationChangeSet | 当前章节 | 作者确认的完整变更集 | 原子提交正文、Canon 与计划补丁 |
| Canon | 项目 | 已确认且已发生的不可变事件流 | 唯一事实源 |
| Projection | 项目 | Canon 的确定性派生快照 | 只读提供状态、记忆、弧光和线索 |
| ContinuityIssue | 项目连续性边界 | 来源、类别、最小处理状态和处理建议 | 记录创作过程债务，不是 Canon、Projection 或 Planning |

统一作者状态词包括：尚未建立、工作草稿、AI 候选、待确认、当前正式版、历史版本、已取代、需要复核、存在阻断、已定稿。页面不得用一个笼统“完成”掩盖对象差异。

## 5. 统一页面骨架

每个业务页面由四层组成：

1. **页面身份**：面包屑、模块名称、一句话职责、当前状态、正式版本和最近更新时间；
2. **当前正式成果**：首屏优先展示作者真正需要阅读的结构化内容；
3. **草稿、候选和历史**：仅在对象确实支持时展示，不强迫所有页面套相同标签；
4. **本页操作**：只展示该对象当前生命周期允许的编辑、AI 生成、比较和确认操作，不包含跨模块推进按钮；契约和圣经确认后不得再显示新草稿、新候选或新修订操作。

正式内容默认展开，技术诊断默认折叠。辅助区域失败时不得让正式成果区域整体失败。刷新和浏览器历史必须恢复当前对象、选定标签、选定卷和选定章节。

## 6. 独立选题中心

### 6.1 市场热门

- 支持注册的公开榜单适配器、手动导入和来源独立状态；
- 目标来源包括起点、QQ 阅读、番茄、七猫、书旗等；
- 正式界面只承诺实际已经可用的适配器，缺失来源先允许导入公开元数据；
- 仅由用户手动刷新，不提供自动刷新和定时调度；
- 不采集章节正文，不绕过登录、验证码、访问控制或站点限制；
- 每个来源显示最后成功时间、数据新鲜度和本次失败，不把旧数据伪装为最新。

### 6.2 AI 选题讨论

用户可以从空白想法直接发起多轮聊天，不依赖市场分析或某条选题方向。用户可以选择附加市场证据、分析、某个方向或候选种子版本。

AI 对话不会自动创建方向、种子或项目。只有用户显式执行“保存为方向”或“保存为候选种子”才形成正式对象。

### 6.3 选题方向

选题方向是可选的中间成果，不是所有讨论的必经步骤。方向至少保存题材机会、目标读者、核心卖点、差异化、风险和来源证据。用户可以继续围绕方向讨论、形成新版本，或直接转为候选种子；空白讨论也可以跳过方向直接保存候选种子。

### 6.4 候选种子库

候选至少展示暂定书名、一句话创意、题材、目标读者、主角、核心欲望、核心冲突、故事承诺、长篇发展空间、市场依据、版本和更新时间。

支持查看、继续讨论、手工编辑形成新版本、另存候选、归档和用指定版本创建项目。被项目引用的历史版本不可物理删除。

### 6.5 创建项目交接

```text
全局候选指定版本
→ 复制内容和来源快照
→ 创建独立项目
→ 项目种子处于待确认
→ 作者检查、修改并确认
→ 进入现有契约链
```

全局候选和项目种子创建后不再双向同步。同一候选可以创建多个彼此独立的项目。

“从候选创建项目”必须是一个 N 类幂等命令，并在同一事务中完成：

1. 校验并钉住全局候选 ID、指定版本、内容 hash 和证据快照引用；
2. 创建项目；
3. 将候选内容复制进现有项目 `creative_seeds / revisions / head` 权威体系；
4. 记录交接来源和幂等结果；
5. 保持项目种子为“待确认”，不得自动确认。

命令失败必须整体回滚，不得留下没有种子的空项目。重试同一幂等键必须返回同一项目和项目种子 revision。不得另建第二套项目种子快照表；项目内后续修改与确认仍调用现有项目 Seed 服务。

## 7. 项目库与项目概览

项目库卡片展示项目名称、题材、当前卷章、已定稿字数、最近更新时间和归档状态。创建项目支持“从候选种子创建”和“空白创建”两条入口。

项目概览首屏展示：

- 作品名、一句话创意和题材；
- 二百万字以上的项目目标及实际定稿字数；
- 当前卷、当前权威章节和最近定稿章节；
- 种子、契约、圣经、规划和写作的真实状态；
- Canon/Projection 是否同步；
- 最近成果和需要处理的连续性问题数量。

模块摘要可以进入对应页面，但概览不提供强制“下一步”主动作，也不重复完整编辑器和下载面板。

## 8. 创作基础页面

### 8.1 创作种子

首屏展示书名、核心创意、主角、核心欲望、核心冲突、故事承诺、题材、目标读者、长篇空间和来源。来自选题中心的项目必须先显示“待确认种子”；用户可修改后手动确认。

### 8.2 创作契约

展示故事发动机、读者承诺、叙事方向、主辅风格、内容边界、质量目标和长篇目标。工作草稿、AI 方案和比较只存在于首次确认之前；作者首次确认后形成唯一永久契约基线，页面只读展示正式内容和生成依据，不再提供克隆、二次确认或新 revision。未来若确需修改已确认契约，必须作为 C 类核心生命周期变更单独设计，不进入 P0。

### 8.3 创作圣经

正式阅读模式按世界与规则、主要人物、势力与关系、核心冲突、长期发展方向、结局锚点和禁止提前发生事项组织。首次确认前允许反复编辑、AI 生成、保存和比较；首次确认后形成永久基线并只读，不允许从正式版创建新草稿、克隆或二次确认。未来若确需修改已确认圣经，必须作为 C 类核心生命周期变更单独设计，不进入 P0，也不得借此修改历史 Canon。

## 9. 世界与连续性

连续性页面是现有 Canon/Projection 的作者视图，不是新的事实库。

### 9.1 设定库

按人物、地点、势力、物品和世界规则浏览。详情明确拆成“未来设计”和“已发生事实/当前状态”两个区域：未来设计读取已确认圣经和 Planning，已发生事实、当前状态、来源章节和证据读取 Canon/Projection。两侧只有存在显式 canonical entity reference 时才能关联；禁止按名称、别名或显示文本自动合并，也不得为统一展示另建第二套人物或设定事实表。新增或调整未来设定只能进入仍允许写入的 Planning；已确认圣经在 P0 永久只读，不能直接写 Canon。

### 9.2 当前状态与记忆

按实体展示当前状态、重要记忆、形成章节、最近更新章节、正文证据和投影 revision。记忆来自 Canon event，不另行调用模型生成第二份权威摘要。

### 9.3 人物弧光

展示当前阶段、目标、信念、关系和能力维度，区分计划节点与已发生节点，并显示来源章节。`arc.*` Canon event 是已发生事实来源；Arc Projection 是作者查看正式派生状态的权威读视图，不接受独立写入。

### 9.4 线索与伏笔

覆盖主线、支线、人物线、谜题、伏笔等 `plot.*` 类型；展示埋设、推进、回收、相关实体、计划回收和实际回收。不得把所有 plot thread 简化为伏笔。

### 9.5 连续性问题

只收纳时间、位置、人物状态、规则和已发生事实冲突，以及需要跨章或未来补偿的问题。本章普通文风和质量建议仍留在本章审核，不进入项目级问题库。

它是 N 类最小边界，持久化内容仅包括项目、类别、严重度、状态、来源章节、来源 Finalization、来源 Canon revision、说明、处理建议、未来处理目标和时间戳。P0 状态只提供“待处理、已解决、不处理”，不增加负责人、截止日期、排期、看板或自动调度。

历史事实有误时创建未来纠偏任务，不能直接重写旧 Canon。ContinuityIssue 不得写入 Projection 或冒充 Planning 节点，也不得直接修改 Canon、历史正文或未来 Planning。

## 10. 故事规划

分卷、情节线、故事块、阶段和场景任务属于未来计划。Story Progress event 属于已发生事实，进入 Canon 后由 Projection 提供只读实际进度。`FinalizationChangeSet` 可以在原子定稿事务中对尚未实现的未来 Planning 节点应用现有白名单 patch；该 patch 不得把计划节点直接标记成已发生事实，也不得移到事务外补写。

### 10.1 分卷规划

展示卷名、卷目标、主要压力、人物重点、预期变化、禁止事件、计划状态和实际进度。

### 10.2 情节线

展示故事问题、未来方向、预期回收、相关人物、计划节点和已发生推进。

### 10.3 故事块

展示进入条件、目标、主要压力、阶段、场景任务、实际完成进度和剩余计划。故事块和阶段可以跨越任意数量章节。

### 10.4 章节小纲

编号章节小纲只针对当前权威章节建立和确认。更远的未来内容保留在故事块、阶段和场景任务中，不提前建立多个可写章节。

小纲展示本章目标、预计人物、承接内容、计划推进、场景、完成证据和禁止提前发生事项。确认 revision 被 ChapterSession 钉住；修改小纲不会静默改变已有工作稿或候选。

## 11. 写作工作台

### 11.1 严格单章串行

任意时刻必须满足：

```text
第 1～N-1 章：已定稿，只读
第 N 章：唯一当前工作章
第 N+1 章以后：仅存在于未来规划，不进入工作台
```

同一当前章可以存在一个可变 WorkingDraft、多个不可变候选和一个活动 FinalizationChangeSet；这不是多章并行。

### 11.2 三栏结构

**左栏：卷章导航**

- 顶部使用卷选择器；
- 下方只显示所选卷的定稿章节和唯一当前工作章；
- 首次进入默认选择最后一卷并定位当前工作章；
- 从历史深链接进入时自动选择该章所在卷；
- 不增加独立“最新章节”按钮；
- 先读取卷摘要，再按稳定卷键读取该卷的有界章节索引；章节索引支持受限分页或游标；
- 索引不返回正文或完整 Planning/Outline JSON，历史章卷归属必须来自定稿时钉住的 Planning/Outline；
- 当前章有已确认小纲时使用其卷引用；尚无可钉住卷时由 bootstrap 返回未分配状态和禁止原因，前端不得猜测；
- 每次只查询和渲染所选卷章节，不一次扫描、加载或渲染全书上千章。

**中栏：正文**

- 点击历史定稿章显示完整定稿正文，只读；
- 点击当前章显示可编辑 WorkingDraft、自动暂存、字数和选区工具；
- 选区工具保留 AI 改写、扩写和缩写，并将旧版“去 AI 腔/润色”明确恢复为“去 AI 味/润色”；
- “去 AI 味/润色”复用现有 `polish_selection` 写链，提示词必须保留剧情、事实、人物意图和信息量，并针对解释腔、套路化反差句、抽象判断、同义反复和机械节奏生成精确替换文本；
- 改对白、加强冲突、加强心理、改网感和改文学化作为 `rewrite_selection` 的作者预设，不新增操作类型或第二套正文写链；P0 不增加可能造成整章事实漂移的一键全文去 AI 味；
- 当前章和历史章都提供“查看小纲”弹窗；
- 历史章小纲必须是定稿时钉住的版本；
- 历史章提供单章下载，卷和整本下载进入项目“导出与备份”；
- 定稿章不能在工作台直接重开或修改。

**右栏：上下文工具**

- 当前章：本章依据、AI 生成、候选比较、审核、ChangeSet 修正与定稿；
- 历史章：定稿小纲、审核结果、Canon 变化、人物状态变化、线索和故事进度，只读；
- 技术 manifest 和内部 revision 放入可展开诊断，不占主要任务区。

工作台首次加载必须调用只读 bootstrap，至少返回请求章号、服务端权威章号、`historical | current | future` 模式、当前会话或定稿引用、可用操作、禁止原因以及 Canon/Projection 同步状态。bootstrap 只负责分类和返回引用，不创建 ChapterSession；真正创建当前章会话仍调用现有显式命令并服从所有前置条件。

### 11.3 章序推进

```text
确认第 N 章小纲
→ 建立唯一 ChapterSession
→ 编辑/生成工作稿
→ 保存候选并审核
→ 作者确认完整 FinalizationChangeSet
→ 原子写入正文、Canon、Projection 和 Planning patch
→ 关闭第 N 章会话
→ 第 N+1 章成为服务端权威章节
```

若 Canon/Projection 不同步、定稿事务未完成或存在活动变更集，下一章不得开放。

## 12. 创作资产与设置

创作资产继续包括风格模板、经验卡和语料档案。题材、阶段、分类和状态在作者界面显示中文；稳定键和内部版本只进入详情诊断。项目绑定具体资产版本后，既有任务继续钉住其版本。

设置只管理 Provider、模型连接、应用默认值和任务模型绑定，不混入创作资产或项目正文。Provider 不可用只禁用相应 AI 动作，不阻止手工编辑和只读查看。

项目“导出与备份”提供单卷、整本定稿下载和项目备份/恢复入口；只导出已定稿正文，不把工作稿或候选混入正式小说文件。项目设置管理作品名称、目标字数和归档等项目级属性。

## 13. 后端影响分类

每个实施任务必须标注一种影响类型：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| F | 纯前端 | 页面重排、中文展示、小纲弹窗 |
| R | 复用现有接口 | 契约、圣经、Planning、当前章和定稿阅读 |
| Q | 新增只读聚合接口 | 工作台 bootstrap、卷摘要、按卷章节索引、连续性详情、历史章审计摘要、项目概览摘要 |
| N | 新增边界上下文和持久化 | 全局讨论、选题方向、候选种子、原子项目交接、ContinuityIssue |
| G | 核心安全加固 | 可选 nullable `active_slot` 单活动 ChapterSession 数据库约束 |
| C | 创作核心语义变化 | 默认禁止纳入本轮，必须单独设计和批准 |

新增 API 必须读取现有权威对象或调用现有命令服务。接口不得在 Router 或前端重新实现业务规则。

Q 类接口只返回作者页面所需的薄 DTO，不复制业务事实、不缓存第二份权威状态，也不在读取时产生写入。卷摘要和章节索引必须有严格的查询上界；历史章审计摘要只聚合现有 Finalization、ChangeSet、Canon 和 pinned authority。

若实施 G 类数据库防御，采用 drafting 时 `active_slot=1`、final 后置空，并以 `(project_id, active_slot)` 的 nullable unique 约束保护。迁移前必须预检和回填；现有项目锁、服务端权威判断和并发测试继续保留，数据库约束不替代服务逻辑。

## 14. 错误、恢复与可访问性

- 普通错误显示在当前操作区域并保留输入；
- 单个辅助区域失败不遮蔽正式成果；
- 长操作沿用现有幂等、lease、恢复和取消语义；
- Provider/外部来源失败不自动重试，不伪造成功；
- 自动暂存失败时阻止危险离开，但允许复制文本；
- 所有写操作显示明确进行状态，禁止重复提交；
- 页面默认中文，键盘、200% 缩放和桌面窄屏保持可用；
- 主滚动容器必须允许鼠标滚轮在内容区正常滚动；
- 不用颜色作为唯一状态信号。

## 15. P0 验收标准

### 15.1 完整真实流程

使用正式本地数据库、默认任务模型绑定和真实 Provider，至少连续完成三章，以验证定稿后的状态传递而不是只验证单章按钮：

```text
手动刷新或导入市场证据
→ 从空白想法或证据发起 AI 讨论
→ 保存并修订候选种子
→ 从指定版本创建项目
→ 在项目内确认种子
→ 建立并确认契约
→ 建立并确认圣经
→ 建立分卷、情节线、故事块和当前章小纲
→ 生成、编辑、保存和比较候选稿
→ 审核并定稿
→ 查看正文、小纲、Canon、状态、记忆、弧光、线索和故事进度
→ 确认下一章在前一章完整提交后才开放
→ 重复完成后续两章并检查跨章承接
```

测试必须使用正式作者页面，不使用 seed 专用 UI、隐藏测试路由或直接数据库写入模拟成功。

三章定稿后，对正文执行人工与模型辅助的质量复核，至少覆盖可读性、情节因果、人物声音、对话、AI 味、章间连续性、情节完整性和重复表达。与本地四十余部合法参考作品只做结构、节奏、人物呈现和确定性复制风险的对照，不要求模仿具体作品，也不得把参考正文大段送给外部 Provider。发现的问题分别归入创作资产、提示词、上下文装配、规划规则或产品交互的独立改进任务，不在验收中临时旁路创作核心。

### 15.2 核心回归门槛

- 现有章节权威、工作稿、候选、审核、Finalization、Canon、Projection、Planning、下载、备份和恢复测试继续通过；
- 路由清单和静态引用检查证明最终只有一个可写工作台组件、一个活动 ChapterSession Store 和一组 Writer 写 API；旧 URL 只能纯重定向；
- 并发请求不同章号时，服务端只允许唯一当前权威章建立 drafting ChapterSession；第二章不能在第一章定稿前建立写作会话；
- 每次成功定稿后断言唯一当前权威章正确推进且 Canon head 与 Projection head 同步；下一章 Session 在其小纲确认并显式创建时必须钉住当时新的 Canon/Planning/Outline 基线；
- 对原子定稿每个故障注入点断言 FinalChapter、Canon、Projection、Planning、Session、ChangeSet 和下一章开放状态全部不推进；
- workbench bootstrap 明确分类历史、当前和未来章，读取不得创建 Session，前端不得以本地推断替代服务端权威；
- 后续 Planning 发生合法变化后，历史定稿正文、正文 hash、钉住小纲及其 Planning/Outline 引用仍保持不变；
- 契约和圣经确认后的 clone、save、再次确认继续被服务拒绝，作者页面不显示对应写入口。

### 15.3 作者体验门槛

- 用户从任一正式页面可以在三次交互内找到当前正式成果；
- 种子、契约、圣经和规划首屏能看见实质内容，不只显示状态卡；
- 上千章项目通过卷选择加载和定位，不渲染全书章节；
- 所有确认、草稿、候选和历史使用统一中文状态词；
- 所有正式成果都有稳定查看入口和来源追溯；
- 页面不存在原始 JSON 占据主内容、英文筛选值、主内容区无法滚动等 Demo 表现。

### 15.4 规模与有界读取门槛

- 使用合成 1000 章以上数据验证卷摘要和按卷章节索引；测试不调用 Provider、不绕过生产查询代码；
- 单次章节索引查询和响应严格受选定卷及分页上限约束，不读取正文或完整 Planning/Outline JSON；
- 前端只渲染当前卷，切换卷和历史深链接能稳定定位，不能退化为先读取全书再在浏览器过滤。

## 16. 实施顺序

1. **A｜核心保护与接口契约**：冻结权威章、原子定稿、Canon/Projection、pinned history 和一次确认生命周期回归；定义 bootstrap、卷索引及 F/R/Q/N/G/C 契约，不改页面和核心语义；
2. **B｜全站壳层与项目概览**：建立全局/项目导航、统一页面骨架、中文状态和项目概览 Q 聚合；
3. **C｜全局选题边界**：建立讨论、证据引用、方向、候选版本和归档，以及进入现有项目 Seed 权威体系的原子幂等交接；
4. **D｜创作基础作者化**：产品化项目种子、契约和圣经的首次确认流程，确认后永久只读；
5. **E｜规划与连续性**：产品化 Planning 和 Canon/Projection 作者读视图；ContinuityIssue 作为独立 N 子计划和独立提交；
6. **F｜统一写作工作台**：实现 bootstrap、卷摘要、按卷索引、三栏工作台、历史只读、选区 AI 工具、历史审计摘要和旧路由纯重定向；
7. **G｜真实与确定性验收**：连续完成三章真实 Provider 作者流程，同时执行核心故障注入、单轨路由检查和千章有界查询；最后审查正文可读性、连贯性、AI 味和长篇连续性，将问题归入独立改进任务。

每一批都必须先通过既有核心回归，再进入下一批。不得为追求页面完成速度跳过架构保护门槛。

本规格是全站总设计，不作为一个超大实施提交。A～G 各自形成范围受控的实施计划和安全提交点；其中 C、E 的 ContinuityIssue 子计划和 F 均拥有独立迁移或回退边界。任何批次不得顺手重写相邻核心模块。

## 17. 设计自查清单

- 无自动刷新、定时选题或无人值守章节生成；
- 无独立章节中心、定稿库、全书生产看板或最新章节按钮；
- 无多章并行工作状态；
- 无强制跨模块“继续下一步”按钮；
- 无第二套人物、记忆、弧光、线索或故事进度事实源；
- 无旧链兼容和新旧双轨；
- 无要求一次完成复杂图谱、时间轴或全平台爬虫；
- 契约和圣经首次确认后永久只读，无隐含后确认修订；
- 全局候选到项目 Seed 为原子幂等复制，无第二套项目种子权威；
- 工作台模式和卷章归属由服务端返回，无前端推断或读取时创建 Session；
- ContinuityIssue 是最小过程债务边界，不写 Canon、Projection 或 Planning；
- “去 AI 味/润色”和专项改写复用现有选区操作，无第二套正文写链；
- 新后端能力均位于现有核心之外或读取现有权威；
- 所有正式成果均有作者可见入口；
- 完整验收使用真实产品路径，而不是为了测试而测试。
