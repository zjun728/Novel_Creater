# 项目资料与项目设置设计

- 日期：2026-09-05
- 基线：`main@ef73a917618fc5559c9659a1c276f150423d86a0`
- 状态：依据已批准的 P0 作者产品设计实施
- 影响类型：B（新增严格 API 与作者页面，不改变 Writer Core）

## 目标

补齐空白项目创建和项目内资料维护，使作者可以明确填写、查看和修改作品名称、题材、项目简介、目标字数与目标章节数。新项目继续默认 2,400,000 字、720 章。

## 产品流程

### 空白创建

“新建项目”弹窗一次展示五项资料：

- 项目名称：必填；
- 题材：可选，允许直接输入；
- 项目简介：可选；
- 目标字数：必填，默认 2,400,000；
- 目标章节数：必填，默认 720。

创建成功后进入项目概览。失败时保留全部输入并在弹窗内显示错误，不自动重试。

### 从候选种子创建

候选种子交接继续由指定候选版本自动复制题材和一句话创意，并使用长篇默认规模。项目种子保持待确认。该弹窗不重复展示候选中已经确定的资料；作者创建后可在“项目设置”调整项目级展示和规模目标。

### 项目设置

项目侧栏“项目配置”增加“项目设置”。活动项目可编辑全部五项，已归档项目只读。页面直接显示当前值、保存状态和字段错误；离开存在未保存修改的页面时使用现有离开保护。

## 后端边界

现有 `projects` 表已经包含全部字段，因此不新增数据库表或迁移。

- `POST /api/projects` 接受五项严格字段，后三项保持后端默认值；
- 新增 `PUT /api/projects/{project_id}/settings`，要求完整五项资料和 `expectedLifecycleRevision`；
- 更新命令在项目行锁内比较 lifecycle revision，并在真正修改时将 revision 加一；
- 归档项目拒绝修改；并发旧 revision 返回现有项目生命周期冲突；
- 原有项目重命名入口保留，避免扩大项目库卡片改造范围。

项目资料只是项目级展示与容量目标，不修改已经确认的种子、契约、圣经、Planning、Canon、Projection、ChapterSession 或定稿内容。

## 前端边界

- 新建独立的 `ProjectCreateDialog`，原 `ProjectNameDialog` 只继续负责快捷重命名；
- 项目 API 只发送五项公开资料，拒绝额外字段；
- Project Store 在服务端成功后才替换项目权威对象，并清除受项目目标影响的概览缓存；
- 新增 `ProjectSettingsView` 和正式路由；项目侧栏只增加一个入口；
- 不新增项目模板、自动推导、重复概览编辑器或强制“继续下一步”按钮。

## 校验与错误处理

- 名称 1–200 字符；题材最多 120 字符；简介最多 5,000 字符；
- 目标字数、目标章节数必须是 JSON 整数且大于零；
- 前端在请求前给出中文字段错误，后端仍是最终权威；
- 保存期间禁用重复提交；请求失败保留本地表单；成功后只采用服务端响应。

## 验收

1. 空白创建会持久化五项资料，默认值可见且可修改。
2. 项目设置刷新后仍显示数据库权威值。
3. 旧 revision、归档状态和非法字段均无法写入。
4. 候选种子交接、人工确认种子和后续 Writer Core 流程保持原行为。
5. 相关后端、前端测试与生产构建通过；无数据库迁移或 Provider 调用。
