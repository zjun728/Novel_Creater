# P0-D 创作基础作者化设计

**状态：** 已经用户逐节确认

**日期：** 2026-08-31

**上位设计：** `docs/superpowers/specs/2026-08-30-p0-author-product-design.md`

**范围：** 项目创作种子、创作契约、创作圣经的作者页面与首次确认体验

## 1. 背景与问题

当前 Seed、Contract、Bible 已有较完整的后端权威、修订、确认和历史能力，但作者页面仍存在明显产品断层：

- 首屏更强调状态或操作流程，作者不能立即看到完整实质内容；
- Contract 以五步向导为主，首次录入尚可，但反复查阅和整体核对成本高；
- Bible 以长表单连续排列，内容层级、完成度和正式阅读态不清楚；
- Seed 候选管理存在，但确认前后的主次关系还不够明确；
- 英文状态、内部 ID、技术信息和业务正文没有彻底分层；
- 三页各自形成不同交互模型，增加学习成本。

P0-D 不重做创作核心，而是把已经存在的权威能力产品化，使作者能清楚完成：

`阅读完整内容 → 编辑草稿 → 保存 → 预览确认 → 永久只读查阅`

## 2. 设计目标

1. 作者进入任一页面后，首屏立即知道页面用途、当前状态、已有内容和缺失项。
2. Seed、Contract、Bible 使用一致的信息架构和生命周期表达。
3. 首次确认前允许安全编辑、AI 辅助、保存和历史核对。
4. 首次确认后形成永久只读基线，不出现隐含的二次修订入口。
5. 完整复用现有 Seed、Contract、Bible 权威，不增加第二套事实源。
6. 不打乱本次 writer-core 重构形成的 Canon、Projection、Planning、Provider 和原子确认边界。

## 3. 方案选择

### 3.1 采用：A「完整内容优先」

页面默认展示完整文档：

- 左侧是文档目录和分区完成状态；
- 中间是完整实质内容；
- 右侧是状态、AI、版本、历史和确认操作。

作者无需先切换步骤，便可判断整份创作基线是否合理。长内容通过左侧目录定位，而不是把正文折叠在多个流程页之后。

### 3.2 不采用：B「分步向导优先」

分步向导能降低首次填写压力，但会产生以下问题：

- 作者难以整体核对契约或圣经；
- 日后查阅正式基线仍需另做阅读页；
- 编辑态与阅读态容易演化为两套结构；
- 延续当前“页面只有流程、完整内容不直观”的问题。

Contract 现有五步能力全部保留，但改为完整文档内的内容分区，不再作为逐页流程门槛。

## 4. 产品结构与职责边界

三页共用生命周期：

`待创建 → 草稿编辑 → 已保存 → 预览确认 → 永久只读`

### 4.1 创作种子

回答“这本书写什么”。

- 可承接选题中心候选，也可在项目内新建；
- 项目中的候选是独立副本，不继续依赖全局候选；
- 确认后项目只有一个权威种子；
- 权威种子成为 Contract、Bible 和后续创作的固定上游。

### 4.2 创作契约

回答“这本书按什么规则写”。

- 绑定已确认 Seed；
- 固化故事发动机、长篇容量、正式资产引用、风格方案和禁止方向；
- 首次确认后永久只读。

### 4.3 创作圣经

回答“这个世界和核心人物如何成立”。

- 绑定已确认 Contract；
- 固化未来创作基线；
- 首次确认后永久只读。

Bible 不承载章节写作后持续变化的当前事实。人物当前状态、记忆、弧光进度、线索进度和故事进度继续由后续设定库、Planning、Canon 和 Projection 展示。

### 4.4 明确非目标

P0-D 不：

- 新建人物、记忆、弧光、线索或进度事实库；
- 修改 Canon、Projection 或 Planning 的语义；
- 改变 Provider 绑定和调用协议；
- 改变写作引擎输入结构；
- 增加自动跳转或强制“继续下一步”按钮；
- 恢复确认后的 clone、重新生成、二次确认或正式基线修改；
- 建设通用低代码表单引擎或 schema 驱动页面系统。

## 5. 统一页面信息架构

### 5.1 页面抬头

每页抬头必须同时显示：

- 中文页面名称；
- 一句话说明该页面解决什么问题；
- 当前生命周期状态；
- 上游基线摘要；
- 是否可编辑。

英文眉题可作为视觉辅助，但不能承担唯一业务说明。

### 5.2 左栏：文档目录

显示：

- 全部分区名称；
- 已填写、建议补充、阻塞三类中文状态；
- 当前定位分区；
- 整体完整度摘要。

目录只负责定位，不是强制步骤。点击目录滚动并聚焦对应正文分区。

### 5.3 中栏：完整文档

- 默认以正式阅读样式展示全部实质内容；
- 点击“编辑当前分区”后，仅当前分区原位进入编辑；
- 保存后返回同一位置的完整阅读视图；
- 数组内容使用可读条目卡片，不用内部 ID 作为主要标题；
- 空分区明确说明缺少什么，不能只显示空白框。

### 5.4 右栏：状态与操作

确认前显示：

- 确认准备度及缺失原因；
- 整份 AI 初稿生成；
- 当前分区 AI 补充或重写；
- 版本、来源和历史；
- 保存状态；
- “预览并确认”主操作。

确认后显示：

- 已确认基线；
- 确认时间和修订；
- 上游来源；
- 历史与诊断入口。

确认后所有写操作从页面消失，而不只是禁用。

### 5.5 响应式布局

- 桌面端使用三栏；
- 中等宽度缩窄目录和状态栏，但保证正文为主；
- 小屏幕改为顶部目录、正文、底部操作的自然单栏；
- 禁止横向滚动；
- 弹窗与抽屉不能长期锁死正文滚动。

## 6. 各页面内容模型

### 6.1 创作种子

确认前先展示候选列表。进入候选详情后使用统一完整文档结构。

正式内容至少包括：

1. 故事标题；
2. 一句话核心；
3. 核心卖点；
4. 主角与起点；
5. 核心冲突；
6. 长期成长路径；
7. 目标读者；
8. 预计规模；
9. 创作边界或禁止方向；
10. 来源与候选版本。

确认后：

- 已确认种子成为唯一主文档并永久只读；
- 其他未选候选进入“历史候选”抽屉；
- 历史候选仅供追溯，不允许切换、编辑或重新确认。

### 6.2 创作契约

首屏摘要显示：

- 已确认 Seed 引用；
- 目标总字数；
- 预计卷数和章节规模；
- 当前草稿修订及确认准备度。

正文分区：

1. 故事发动机；
2. 长篇容量；
3. 正式资产范围；
4. 风格方案；
5. 禁止方向；
6. 完整预览。

现有故事发动机生成、容量配置、资产选择、风格选择和风格试写能力回到对应分区。只有最终“预览并签印”要求所有必填项和上游依赖满足。

### 6.3 创作圣经

首屏摘要显示：

- Contract 基线；
- 当前草稿修订；
- 世界规则、核心人物和势力数量；
- 完整度及开放问题数量。

正文分区：

1. 作品承诺；
2. 世界规则；
3. 力量／成长体系；
4. 核心人物初始设计；
5. 势力；
6. 长期冲突；
7. 关系动力；
8. 叙事语气与边界；
9. 连续性护栏；
10. 开放设计问题。

Bible 只展示未来设计，不展示或写入章节写作后产生的当前状态。

## 7. 编辑、AI 与确认交互

### 7.1 原位编辑

- 同一页面兼具阅读和编辑；
- 每次只解锁一个分区；
- 离开未保存分区时明确提醒；
- 保存只产生草稿修订，不等同于确认；
- 切换项目时清理本地临时状态，不能污染其他项目。

### 7.2 AI 辅助

提供两级能力：

1. 整份初稿生成；
2. 当前分区补充或重写。

共同规则：

- 只在确认前提供；
- 复用现有 Provider 绑定和 generation-attempt 链路；
- 生成结果先进入差异预览；
- 用户可逐项或整区采纳；
- 未采纳结果不能覆盖已保存内容；
- AI 不自动保存、不自动确认、不自动跳转。

### 7.3 最终确认

确认弹窗展示：

- 完整快照；
- 上游基线和来源版本；
- 当前修订；
- 不可逆说明；
- 明确的返回编辑和确认操作。

确认成功后停留在当前页面并切换到只读态。后续页面由用户通过项目导航手动进入。

## 8. 数据权威与接口边界

权威链保持：

`Confirmed Seed → Confirmed Contract → Confirmed Bible → Planning → Canon/Projection`

### 8.1 通用原则

- 不新增 Seed、Contract 或 Bible 权威表；
- 不为页面展示复制正式正文；
- 页面读取服务端 head、draft、history、revision、hash 和 capability；
- 前端不自行推断最终写权限；
- 冲突时保留本地内容并重新读取权威版本，不静默覆盖；
- 已归档项目全页只读。

### 8.2 Seed 接口

复用现有项目 Seed 列表、创建、更新、归档、恢复、删除和 selected-seed 原子确认接口。

确认必须继续校验：

- seed revision；
- selection revision；
- 项目状态；
- 候选 capability。

### 8.3 Contract 接口

复用：

- contract draft 读取和保存；
- preview；
- confirm；
- head；
- history。

确认后的 save、clone、preview 生成和再次 confirm 必须由服务端拒绝。历史或兼容路由即使暂时存在，也不能成为作者页面入口或绕过永久基线保护。

### 8.4 Bible 接口

复用：

- bible head；
- bible draft 读取和保存；
- generate 和 generation-attempt；
- confirm；
- history 及 history detail。

确认后的 save、clone、generate 和再次 confirm 必须由服务端拒绝。

### 8.5 允许的最小接口调整

仅当现有返回无法支持页面展示时，允许：

- 补充只读摘要字段；
- 补充中文展示所需的稳定枚举；
- 补充服务端 capability 或 blockedReasons；
- 补充分区完整度所需的只读投影。

不得因此新增第二套写接口、持久化副本或前端直连 Provider。

## 9. 状态与异常处理

| 状态 | 主内容 | 可用操作 |
|---|---|---|
| 无草稿 | 解释性空态 | 创建或生成初稿 |
| 草稿编辑 | 完整草稿 | 编辑分区、AI 辅助、保存 |
| 已保存 | 完整草稿 | 编辑、历史、预览确认 |
| AI 处理中 | 正文仍可读 | 锁定相关重复操作 |
| 保存冲突 | 本地内容保留 | 重新加载权威版本、手动处理 |
| 已确认 | 完整正式内容 | 历史、来源、诊断 |
| 已归档 | 完整只读内容 | 历史、来源 |
| 加载失败 | 当前页错误说明 | 原地重试 |

错误不得跳到其他项目，也不得用空白页伪装成功。

## 10. 中文化与技术信息分层

- 生命周期、能力、阻塞原因和筛选项使用中文；
- stable key、内部 ID、hash 和 correlation ID 不作为正文标题；
- 技术标识只进入“来源与诊断”详情；
- 原始 JSON 不进入作者主界面；
- 英文眉题只作装饰，不能取代中文业务名称。

## 11. 无障碍与交互质量

- 目录、编辑、保存、预览和弹窗全部支持键盘；
- 弹窗关闭后焦点返回触发入口；
- 状态变化使用适当 live region，但避免重复朗读；
- 主内容区和页面滚动关系明确；
- 弹窗、抽屉关闭后恢复原滚动位置；
- 小屏幕不依赖 hover 才能发现操作；
- 低动态偏好下关闭非必要动画。

## 12. 实现结构建议

只抽取三页真正共用的轻量组件：

- 基础文档页面壳；
- 分区目录；
- 状态与操作栏；
- 文档分区容器；
- AI 差异预览；
- 最终确认预览。

Seed、Contract、Bible 的字段、校验和命令仍由各自 store/controller 管理。禁止为了复用而建设通用 schema 表单引擎。

## 13. 验收标准

### 13.1 产品体验

- 从项目导航进入任一页面，首屏可见页面用途、当前状态和实质内容；
- 三次交互内可找到完整正式内容、历史来源或确认操作；
- 中文业务界面不出现无解释的英文枚举和内部字段；
- 桌面端三栏和小屏幕单栏均无横向溢出；
- 页面正文、抽屉和弹窗滚动正常。

### 13.2 生命周期

Seed、Contract、Bible 各验证一次：

`草稿编辑 → 保存 → 预览 → 确认 → 只读`

并验证：

- 一次修订冲突恢复；
- 一次归档只读；
- 一次 AI 结果预览和采纳；
- 确认后前端无写入口；
- 确认后服务端拒绝写命令。

### 13.3 工程验证

- 相关前端单元测试；
- 相关后端 API 和服务测试；
- 生产构建；
- 一条本地浏览器完整路径。

P0-D 使用确定性数据验收，不执行真实文章生成、Stage A/B、数据库迁移或额外 Provider 消耗。真实长篇生成留给 P0-G。

## 14. 视觉决策参考

本轮决策草图：`tmp/p0-d-foundation-layout-options.html`。

草图仅用于信息架构确认，不是生产代码，也不规定所有像素细节。正式实现必须沿用当前产品的编辑部／纸张视觉语言，并以真实数据密度、响应式和无障碍表现为准。

## 15. 设计自检

- 没有新增第二套 Seed、Contract 或 Bible 权威；
- 没有改变 writer-core、Canon、Projection、Planning 或 Provider 边界；
- 没有恢复确认后修订；
- 没有增加自动下一步；
- 没有把人物状态、记忆、弧光和线索写回 Bible；
- 没有建设通用表单引擎；
- 没有为了验收引入真实文章生成或复杂发布流程；
- 页面优先展示实质内容，而不是状态卡或流程壳。
