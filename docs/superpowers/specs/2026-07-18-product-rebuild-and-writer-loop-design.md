# Novel Creator 产品重构与长篇写作闭环设计

- 日期：2026-07-18
- 产品基线：`main@b8c7519`
- 当前运行形态：本机单用户
- 首个样板：男频穿越长篇《典镇山河》
- 目标平台倾向：起点、QQ 阅读型；优先覆盖穿越、玄幻、仙侠、高武
- 状态：作者已逐节确认

## 1. 产品目标

Novel Creator 的首要目标不是追求高文学性、复杂修辞或宏大社会深度，而是帮助作者持续写出一部长篇、连贯、可控并且让人愿意继续读的小说。

“愿意继续读”具体意味着：

- 情节不是干巴巴地执行任务，而是持续发生有因果、有阻力、有结果的变化；
- 场景有过程、反应和余波，不像大纲扩写、历史材料或文献摘要；
- 人物有自己的欲望、判断、声音和行动，不只是剧情工具；
- 对话符合人物身份、关系和当时情绪，包含自然的停顿、回避、潜台词与误解；
- 情绪来自具体处境、行为和内心选择，而不是反复套用身体反应；
- 读者关心人物和事件接下来会怎样，但不强制每章制造悬念或章末钩子；
- 作者始终拥有最终决定权，模型只能提供建议、候选和分析，不能擅自定稿或改写历史。

平台价值不能依赖为每本小说重新开发一套专属系统。平台提供稳定的通用创作内核；每本书通过种子、故事发动机、创作契约、圣经、风格、经验卡、语料引用和后续规划形成自己的“本书创作契约”。

## 2. 设计原则

### 2.1 单一事实源

已定稿正文只提取一次结构化变化，生成一个完整的 `FinalizationChangeSet`。作者一次查看、一次确认，后端一次事务提交。

Canon 是唯一权威事实源。设定库、记忆、人物弧光、伏笔、人物当前状态和故事块进度都是同一批已确认 Canon 变化的不同视图，不得分别再次读取正文、分别调用模型或分别维护冲突状态。

“只提取一次”特指 Canon、人物状态、故事块进度和派生视图只执行一次结构化事实提取。质量模型和确定性复制检查可以读取候选正文，但不得提取、创建或写入 Canon 事实。

### 2.2 已发生事实与未来计划分离

每个相关页面都明确区分：

- **已发生事实**：来自已定稿正文，带生效章节，只读；
- **未来计划**：预计关系变化、人物方向、待展开伏笔、故事块安排等，可调整。

模型生成时可以同时读取两层，但必须清楚区分“已经发生”和“准备发生”。定稿历史不允许重开、替换或回滚；如历史事实有误，只能建立从未来章节开始生效的纠正。

### 2.3 作者控制，AI 辅助

- AI 结果先进入工作稿、候选或建议，不得直接成为定稿事实；
- 质量审核是诊断和建议，不能为了追求评分自动改文；
- Canon 硬冲突、正文不完整和明显复制风险可以阻止定稿；
- 普通质量问题不设置机械及格分，作者仍可决定定稿；
- 风格模板和经验卡是软指导，不是逐条打卡规则。

### 2.4 最小状态和最少操作

界面只保留一个与当前状态匹配的主动作。能自动完成的暂存、上下文装配、状态同步和版本记录不要求作者重复确认。

不可逆操作必须明确确认；可撤销操作直接执行并提供撤销。生成和定稿期间通过统一只读遮罩阻止冲突，不建立大量难以理解的按钮禁用组合。

### 2.5 不兼容旧链路

当前仍处于开发阶段，不需要兼容旧数据库、旧 Store、旧 API、旧写作页或历史测试数据。符合新设计的能力重建后，旧路径直接删除，不保留双轨逻辑。

旧界面只可借鉴成熟的三栏布局、版本对比和防丢稿体验；旧写入、旧定稿和旧 Canon 处理不得重新接回正式链路。

## 3. 当前基线与重构边界

当前有效写作页是简化的 `ChapterWriterView.vue`。它只能完成创建章节会话、生成或保存一个工作稿、保存候选，尚未形成完整写作闭环。

已确认的主要缺口包括：

- AI 生成和保存响应可能覆盖作者刚输入的文字；
- “保存为候选”可能冻结服务端旧稿，而不是编辑器中看到的正文；
- 多个写动作使用独立 busy 标记，仍可并发冲突；
- 当前活动页面没有候选加载、对比、融合、审稿和原子定稿；
- 当前项目上下文在离开项目页后被清空；
- 项目删除实际是归档，但界面宣称不可恢复；
- 普通成功、信息、警告和错误被做成阻塞式弹窗；
- 创作资产被放在设置中，项目中心和旧成熟模块断开；
- 活动 UI 没有安全的小说下载和项目备份；
- 旧定稿流程先提交正文再执行后处理，不能满足全事务回滚。

本规格重建正式产品链，不将旧页面重新挂回路由。

## 4. 产品信息架构

### 4.1 全局导航

未打开项目时，全局导航只有：

1. 项目库
2. 创作资产
3. 设置

打开项目后，导航增加当前上下文：

- 当前项目名称；
- 项目中心；
- 写作台及当前章节。

不设置底部“返回项目库”。切换项目统一进入项目库完成。

### 4.2 项目库

项目卡片本身不承担跳转，使用明确的“打开项目”按钮。

卡片动作：

- **打开项目**：进入项目中心；
- **继续写作**：仅当项目存在活动工作稿或未完成章节会话时显示；
- **更多**：编辑项目名称、归档。

有活动工作稿时，“继续写作”是唯一主按钮，“打开项目”降为次级文字按钮；没有活动工作稿时，“打开项目”是唯一主按钮。卡片不会同时出现两个同层级主动作。

归档可撤销，不弹确认。项目库提供“已归档”视图，允许恢复。永久删除只允许在已归档列表中执行，并使用一次危险确认。

新建项目只要求项目名称。创建成功后直接进入项目中心。

项目库页头提供次级“导入项目备份”入口。导入只创建新项目，不与项目卡上的备份动作混在一起。

### 4.3 项目中心

“打开项目”默认进入项目中心。项目中心只保留一套模块导航，不再同时展示流程卡、Tabs 和多个重复入口。

模块分组：

| 分组 | 模块 |
| --- | --- |
| 创作准备 | 选题与种子、创作契约、创作圣经 |
| 故事规划 | 分卷规划、情节规划、故事块 |
| 小说事实 | 人物、势力、地点、物品、世界规则、时间线 |
| 状态视图 | 记忆、人物弧光、伏笔与未完成情节 |
| 内容管理 | 章节与定稿记录、修订历史 |
| 项目设置 | 模型绑定、数据状态 |

模块位置写入 URL，刷新、浏览器前进后退和直接访问都能恢复。路由中的项目 ID 是上下文来源，不能依赖某个页面组件挂载时临时保存项目。

项目中心顶部只显示一个动态“下一步”，按以下优先级计算：

1. 正在执行写入或定稿：查看当前操作；
2. Canon 与 Projection 不同步：重建状态视图；
3. 存在自动暂存失败的活动工作稿：返回写作台恢复正文；
4. 存在仍有效的活动 Session 或工作稿：继续写作；
5. 未选择种子：选择种子；
6. 未确认契约：继续创作契约；
7. 未确认圣经：继续创作圣经；
8. 缺少当前规划或小纲：补充下一项规划；
9. 已具备写作条件：进入写作台。

小说下载位于项目中心页头。项目备份位于项目中心“更多”菜单。归档只位于项目库项目卡“更多”菜单，避免重复入口。

“已具备写作条件”不是一个笼统布尔值。系统分别计算：

- 可进入写作台；
- 可手工编辑；
- 可调用 AI；
- 可保存候选；
- 可定稿。

Provider 或模型绑定不可用只阻止相应 AI 动作，不阻止手工写作、查看、下载或备份。

模块内只读选中项可以使用 `?selected=<stable-id>` 恢复；正在编辑的弹窗和未提交表单不写入 URL。无效 module、无效章节号和未知路由进入明确的 Not Found 页面，不再静默跳回项目库。访问已归档项目时显示只读归档状态页，提供“恢复项目”和“返回项目库”。

浏览器返回必须恢复模块和只读选中项。任何旧深链接如果已经删除，显示“此入口已升级或不存在”，并提供项目库入口，不能偷偷进入错误模块。

### 4.5 写作台

写作台使用三栏结构：

- 左栏：章节、当前分卷、故事块、阶段、情节任务和本章小纲；
- 中栏：当前工作稿编辑器；
- 右栏：候选稿、质量审核、对比融合和本章参考依据。

页面根据状态只显示一个主动作：

1. 开始下一章；
2. 生成或确认本章小纲；
3. AI 生成新工作稿；
4. 保存为候选；
5. 审查并定稿；
6. 开始下一章。

选中文字后才出现局部改写、扩写和压缩工具。两个候选被选中后才出现对比和融合入口。

当前版本以桌面写作为主：1280×720 及以上是完整验收范围，1440px 和 1920px 宽度重点优化。较窄桌面将左右栏折叠为可呼出的面板，不能缩窄中央正文到难以阅读。手机端正式写作不属于当前版本完成标准，但项目库、只读章节和下载页面不能完全不可用。

## 5. 创作资产与设置

### 5.1 创作资产

“创作资产”是全局一级页面，不属于设置，包含：

- 10 套已批准风格模板；
- 64 张已批准经验卡；
- 本地语料库。

这是个人本地创作平台，不建立审核、上架、发布、运营或管理员流程。

系统风格和经验卡只读。页面提供浏览、搜索、筛选和详情；项目在创作契约中选择并冻结具体版本。每个新项目不重新分析本地几十本小说，也不重新联网建立风格库。

本地语料库可以保存小说原文或节选。原文只用于个人检索、分析和写作参考；系统不得输出大段原文或直接复制。项目契约冻结实际引用的素材版本和必要片段，保证后续可复现。

语料的导入、浏览和管理均在“创作资产”完成。设置页不再重复提供资产管理。

语料导入将内容复制到应用管理的内容寻址存储，而不是只保存外部文件路径。每次内容变化产生不可变新版本；移动或删除原始文件不影响已经导入的版本。被契约或历史 manifest 引用的版本不可物理删除，只能归档；未引用版本永久删除需要一次危险确认。

契约中的资产推荐采用“确定性筛选＋模型排序”：

1. 确定性规则先排除题材、适用阶段、禁用方向或版本状态明确不符合的资产；
2. `seed` 模型根据种子、故事发动机和已选风格，对剩余资产排序并给出简短理由；
3. 推荐置信度不足或没有匹配项时，直接开放完整资产浏览，不伪造推荐；
4. 推荐结果永远不会自动选中，最终引用由作者决定。

### 5.2 设置

设置只包含：

- Provider 与模型；
- 新项目默认模型规则；
- 本机应用配置与诊断。

Provider 卡片可以执行安全连接测试。测试由后端使用已保存凭据完成，只返回：

```json
{
  "ok": true,
  "code": "connected",
  "latencyMs": 123,
  "publicMessage": "连接成功"
}
```

任何 API 响应、错误、日志、小说下载、项目备份或诊断信息都不得包含明文 API Key、Authorization、Token、Password 或其他秘密。Base URL 也不作为普通公共摘要返回前端。

编辑 Provider 时密钥字段永远为空：

- 留空表示保留原秘密；
- 输入新值表示替换；
- 清除秘密是危险操作，必须二次确认。

作者输入的新秘密只允许短暂存在于受控表单内存和发往本机后端的单次请求体。它不得进入 Pinia 持久 Store、localStorage、sessionStorage、URL、分析事件、日志、错误或诊断；请求结束后立即清空字段和临时变量。

所有 Provider 调用都从后端 AI gateway 发起，正式前端不得直接连接 Provider。

### 5.3 项目模型绑定

全局设置管理可用 Provider、模型和新项目默认规则。项目实际模型绑定放在“项目中心 → 项目设置”查看和调整。

新建项目的绑定规则：

1. 优先继承创建时间最近、未归档且绑定仍 Ready 的项目完整绑定；创建时间相同按项目 ID 稳定排序；
2. 上一个项目没有有效绑定时，优先使用作者在全局设置中明确选择的 fallback 模型；
3. 没有明确 fallback 或它已不可用时，使用模型列表中按稳定顺序排列的第一个已启用模型；
4. 没有可用模型时项目可以创建，但 AI 动作显示明确恢复入口。

全局设置可配置的“新项目默认规则”只包含 fallback 模型；“优先继承最近有效项目”是固定产品规则，不能被切换成难以预测的模式。

默认界面只显示一个模型选择器，并将同一模型绑定到全部八类任务。高级设置才展开八项独立绑定。保存始终原子替换完整绑定快照。

八类模型任务正式定义如下：

| 存储键 | 用户名称 | 职责 |
| --- | --- | --- |
| `market` | 市场选题 | 分析榜单、趋势和题材机会 |
| `seed` | 种子与故事发动机 | 生成、完善种子和发动机方案 |
| `planning` | 创作规划 | 圣经、分卷、情节、故事块和章节小纲 |
| `writing` | 正文写作 | 生成新的章节工作稿 |
| `polish` | 改写润色 | 全文改写、局部改写、扩写、压缩和候选融合 |
| `audit` | 质量审核 | 故事质量、AI 味、人物、对话、连贯性和复制风险 |
| `extraction` | 定稿提取 | 一次读取候选正文并生成完整 `FinalizationChangeSet` |
| `summary` | 上下文压缩 | 必要时压缩已确认 Canon 和既有摘要，不创建事实 |

调整绑定只影响该项目之后的新任务，不回写已经生成或定稿的内容。每次 AI 结果记录实际 Provider、模型和绑定 revision。

## 6. 选题、种子、创作契约与圣经

### 6.1 选题不是正式实体

榜单、趋势、抓取结果和 AI 选题问答都是灵感与上下文，不建立单独的“选题实体”。来源、时间和必要说明保存为种子的 provenance。

AI 选题聊天不会自动创建种子。作者明确点击“保存为种子”后才进入项目。

市场数据由独立的来源适配器采集，不让模型自行声称“已经全网检索”。每条榜单快照至少记录平台、榜单名称、分类、名次、作品公开信息、抓取时间、来源 URL 和内容 hash。不同来源先分别保存，再进入统一的趋势分析视图；平台不把不同口径的名次简单混成一个虚假总榜。

采集支持手动刷新和计划刷新。单个来源失败时保留最近一次成功快照，并明确显示数据时间与失败状态。来源适配器不得绕过登录、验证码、访问控制或站点明确禁止的技术边界。无法自动采集的来源允许作者导入公开榜单快照。

`market` 模型任务只分析这些带来源、带时间的已采集数据，输出“当前热度、增长方向、拥挤程度、潜在机会和不确定性”，不能把预测表述为事实。分析结果仍只是种子灵感，不进入 Canon。

### 6.2 种子

一个项目可以创建任意数量的种子，不固定为三个。种子可以由 AI 生成，也可以手工添加。项目最终只能选择一个种子进入创作契约。

第一章定稿前允许切换种子。切换后：

- 原契约 revision 保留；
- 项目 aggregate 只有一个 `activeSeedSelectionRevision`，切换种子时单调递增；
- 旧契约、圣经、规划、ChapterSession、工作稿和候选都保留，并继续钉住原来的 seed selection/contract/bible/planning revision；
- 与当前 selection revision 不一致的旧下游内容标记为 superseded，只读历史可查看，不被删除，也不能整体重新激活为活动分支；
- 新的活动链路从创作契约开始，必须重新确认契约、圣经和必要规划后才能继续 AI 写作；
- 项目中心主动作立即变为“继续创作契约”，不再显示旧分支“继续写作”；
- 不弹额外确认框。

重新选择以前用过的种子仍会产生新的 `activeSeedSelectionRevision`，不会复活旧 Session 或旧写作状态。作者可以查看和复制 superseded 内容作为参考，但必须在当前 revision 下生成新的契约和下游实体。平台不引入可切换的多活动创作分支模型。

正在执行写入或定稿时不能切换种子，由当前操作遮罩直接阻止。第一章定稿后，选定种子和所有已引用种子不可编辑、不可切换；未引用候选仍可永久删除并确认，历史引用种子可以归档和恢复，但不能物理删除。

### 6.3 创作契约

选定种子是进入契约模块的前置条件，由“选题与种子”模块完成，不再作为契约内部的重复步骤。契约流程：

1. 系统生成三个故事发动机方案，或作者使用普通表单手工填写；
2. 选择主风格、辅风格，阅读示例，并可进行风格试写；
3. 系统推荐少量相关经验卡和语料，作者选择；
4. 设置目标长度、容量、明确禁止方向；
5. 作者一次确认完整契约。

手工故事发动机使用正常字段表单，不暴露原始 JSON。结构化方案生成只遮罩创作契约当前模块，不锁死全应用，也不要求在编辑器中流式展示 JSON。

确认后的契约只读。后续调整建立新 revision，旧 revision 保留，只影响未来内容。

### 6.4 创作圣经

契约确认后生成创作圣经，作者可以编辑并确认。圣经不允许删除或重置，只建立 revision 历史。

圣经确认前不能进入正式故事规划和正文生成。确认后，圣经中的未来设计仍可通过新 revision 调整，但不能篡改已发生 Canon。

## 7. 故事规划与故事块

故事块的目的不是规定固定章节数量，而是保存一段可滚动推进的完整情节。

- 一个故事块可跨越任意数量章节；
- 一个阶段可以跨章延续；
- 不要求每章完成一个阶段；
- 不要求每章设置钩子或悬念；
- 当前章接近安全字数上限时，不开启新的场景；
- 当前正在发生的场景允许自然结束；
- 剩余情节自动留在当前故事块的下一未完成阶段，供下一章继续；
- 不再提供误导性的“拆分未定稿内容”动作。

分卷规划、情节规划和故事块属于未来计划。定稿后，实际完成进度由同一个 `FinalizationChangeSet` 更新。

故事块必须区分：

- **实际完成事实**：写入 Canon event，再由投影得到只读的实际进度；
- **未来剩余计划**：保存在 Planning aggregate，可以继续调整。

`FinalizationChangeSet` 同时携带已发生的进度事件和对未来计划的明确 patch，但不得在 Canon 投影和 Planning 中分别保存两份权威“已完成状态”。ChapterSession 固定本章使用的 StoryBlock、Stage、SceneTask 稳定 ID 和 revision；提取结果只能引用这些稳定 ID，不能临时创造一个不存在的“已完成阶段”。

进度允许部分完成并跨章延续；已经完成的事实只能单调前进，不能从 completed 改回 pending。若当前故事块已经完成且没有下一块，下一章主动作变为“准备下一个故事块”，不能直接生成正文。

章节采用手动逐章生成和逐章定稿，不做无人值守连续生成。

### 7.1 章节小纲生命周期

`ChapterOutline` 是带 revision 的规划实体，来源可以是：

- 系统根据当前故事块未完成阶段生成；
- 作者手工创建；
- 作者在 AI 草案上继续编辑。

小纲至少包含本章目标、预计出场人物、承接的未完成情节、计划推进的阶段、主要场景和明确不应提前发生的内容。作者确认后，该 revision 才能用于正文生成。

生成 WorkingDraft 时固定 `chapterOutlineRevision`。工作稿或候选已经存在后，作者仍可建立新版小纲；旧工作稿和候选继续钉住旧 revision，不被删除或静默失效。作者明确点击“以新版小纲重新生成”后，新 revision 才成为下一份工作稿的输入。

下一章默认从 Canon 投影中的未完成 StoryBlock/Stage/SceneTask 生成小纲草案，但仍必须由作者确认。小纲修改不能直接更改 Canon，也不能把未发生计划标记为已完成。

## 8. 本章上下文组装

系统不把整本圣经、全部设定、64 张经验卡和全部语料一次性塞给模型。每章自动装配一个有预算、可追溯的精简上下文包：

1. **硬约束**：已发生 Canon、人物当前状态和世界规则；
2. **当前任务**：本章小纲、正在进行的故事块、目标情节；
3. **连贯依据**：上一章正文、近期章节摘要、未解决情节；
4. **场景资料**：本章实际涉及的人物、地点、物品和关系；
5. **写作指导**：本书主辅风格，以及按需检索出的少量经验卡和语料片段；
6. **作者临时要求**：只对本次动作生效，优先于软性指导，但不能突破 Canon 硬事实。

设定和 Canon 负责“不写错”；风格、经验卡和语料负责“怎么写得好”，不能变成模型逐条完成的硬规则。

写作台提供可展开的“本章使用依据”，展示本次实际使用的 Canon revision、规划、风格、经验卡和语料片段。默认折叠，不增加作者操作。

`summary` 模型任务只在上下文确实超过预算时，对已确认 Canon 和既有结构化摘要做非权威压缩。它不得重新读取正文、生成新事实或覆盖 Canon。

## 9. 工作稿、候选稿与写作操作

### 9.1 生命周期

每章只有一个当前 `WorkingDraft`。它是可变工作区，通过防抖自动暂存。自动暂存永远不会创建候选。

为实现恢复和断线续查，数据层明确区分：

- `WorkingDraft`：唯一可变的当前工作区；
- `WorkingDraftRevision`：AI 成功写入、候选载入、全文改写等关键替换前后形成的不可变恢复记录；
- `DraftOperationAttempt`：一次生成或修改操作的输入 manifest、流式状态、中断 buffer、错误和最终结果；
- `Candidate`：作者明确冻结的不可变候选。

AI 成功时在一个短事务中保存旧 `WorkingDraftRevision`、写入新的 `WorkingDraft` 并完成 `DraftOperationAttempt`。中断输出只属于 attempt，不能伪装成工作稿 revision 或候选。

编辑器底部固定显示：

- 当前字数；
- 目标字数区间；
- 暂存状态：未暂存、正在暂存、已暂存时间、暂存失败。

界面不显示“保存工作稿”按钮。

`Candidate` 是不可变快照。作者点击“保存为候选”时，后端必须原子完成：

1. 前端立即进入 `starting` 只读遮罩，冻结本地 buffer generation，停止 debounce 并强制 flush 当前编辑器正文；
2. 等待暂存成功，取得服务端 `workingDraftRevision` 和 `contentHash`；
3. 发送 `sessionId`、`expectedWorkingDraftRevision`、`expectedContentHash` 和 `idempotencyKey`；
4. 后端在事务中锁定 WorkingDraft 并校验 revision 和 hash；
5. 冻结当前可见正文为一个候选；
6. 同一幂等键和相同请求指纹返回同一 Candidate；同键不同指纹返回冲突。

候选保存不能冻结旧服务端内容。

### 9.2 生成与修改语义

- “AI 生成工作稿”始终根据本章小纲和上下文生成一篇新稿；
- 有现有内容时按钮明确为“重新生成新工作稿”；
- 旧工作稿先保存为可恢复记录，不要求作者提前保存候选；
- 只有作者点击“改写全文”才以当前工作稿为基础；
- 局部改写、扩写和压缩只处理明确选中的精确文本范围；
- 作者临时要求只作用于当前一次操作；
- “载入候选”把候选复制为新的工作稿，不修改候选；
- 最多选择两个候选并排对比；
- 融合结果先成为工作稿，作者确认后才能保存为新候选；
- 定稿只能使用一个已保存候选。

候选展示名称、创建时间、字数、来源动作、模型、内容 hash 和检查状态，不向作者暴露无意义的内部 revision 数字作为主要信息。

局部操作请求必须包含 `baseWorkingDraftRevision`、`startOffset`、`endOffset`、`selectedTextHash`、操作类型和作者要求。后端重新校验 revision、范围和选中文本 hash，不使用字符串搜索替换。

### 9.3 自动暂存与离开

正常情况下，作者可以直接离开写作台。只有以下情况阻止离开：

- 自动暂存失败，存在尚未落库的正文；
- AI 写入或原子定稿仍在执行。

应用内路由跳转使用统一应用内对话框。刷新或关闭标签页时，浏览器无法可靠显示自定义弹窗，因此只在存在未落库正文或关键操作进行中时注册原生 `beforeunload`；正常已暂存状态不注册拦截，也不依赖自定义提示文案。

## 10. 流式输出与统一操作遮罩

生成新稿、全文改写、局部改写、扩写、压缩和融合必须展示流式输出。

AI 操作开始前：

1. 点击动作后立即进入 `starting` 只读遮罩并冻结本地 buffer generation；
2. 停止 debounce 并 flush 自动暂存；
3. 等待服务端确认新的 revision 和正文 hash；
4. 后端以 expected revision/hash 原子取得该项目的单一活动写 lease；
5. 固定输入 revision、模型绑定 revision、上下文 manifest 和幂等键；
6. 整个写作台保持只读；
7. lease 存续期间拒绝新的自动暂存。

任一步失败都解除 `starting`，恢复同一份本地 buffer，不得清空作者输入。

遮罩行为：

- 编辑器覆盖约 8%–12% 的透明浅灰交互层；
- 不模糊、不深色化正文；
- 左右侧控制区域适当弱化；
- 编辑器可通过滚轮上下查看，但不能编辑、粘贴、触发选区工具或切换章节；
- 默认自动跟随最新输出；
- 用户向上滚动后停止自动跟随，显示“回到最新输出”。

流式内容先进入独立 UI buffer，不边流边覆盖正式 `WorkingDraft`。每条事件携带 `operationId` 和单调递增 `sequence`。后端事件协议至少包含：

- `started`：操作 ID 和安全公共状态；
- `delta`：新增正文片段；
- `heartbeat`：维持连接和活动 lease；
- `completed`：完整内容 hash、工作稿 revision 和安全元数据；
- `failed`：稳定错误码、公共消息和是否保留中断内容。

服务端先提交新的 WorkingDraft，再发送 `completed`。客户端断线后使用最后一个 `sequence` 重连；事件无法续传时按 `operationId` 查询 operation 状态和已提交结果，不能重新生成。partial output 设置明确的保留期限和大小上限。

成功时后端一次提交新 `WorkingDraft`，前端再替换编辑器。失败时原工作稿保持不变；已经显示的部分输出保存为“中断的临时输出”，不是候选，作者可以恢复查看、继续生成或放弃。

生成类操作允许安全取消；取消只终止当前 attempt，不改变原工作稿。原子定稿进入数据库提交阶段后不可取消，只能查询结果。活动命令具有 lease、heartbeat、超时和过期恢复规则，应用或 Provider 崩溃不能永久锁住项目。

每次取得 lease 都分配单调递增的 fencing token。AI 结果提交事务必须锁定 ChapterSession，并重新验证 active operation ID、fencing token、base WorkingDraft revision/hash、session 仍为 drafting 且 Canon/Projection 仍同步。lease 已过期或被新操作替代的旧结果只能保存为 attempt 记录，禁止覆盖当前 WorkingDraft。

AI gateway 对外声明 Provider 是否支持流式输出。支持时传输真实增量；不支持时显示持续进度并最终发送一次 `completed`，不得把完整结果人工切片伪装成模型流。

同一项目同时只允许一个会改变写作状态的命令。自动暂存不算长操作，但必须在长操作开始前完成。

## 11. 质量审核与“愿意继续读”标准

### 11.1 检查时机

- “保存为候选”只冻结版本，不自动调用模型；
- 作者可以在任何已保存候选上点击“质量检查”，工作稿不直接产生正式检查记录；
- 点击“审查并定稿”时，对选定候选执行完整检查；
- 检查记录绑定候选内容 hash、Canon revision、契约/圣经 revision、审核策略版本、复制语料 manifest、模型绑定 revision 和检查器版本；
- 作者从候选载入后继续修改并保存出的新候选必须重新检查；原候选及其检查结果保持不变。

### 11.2 质量维度

| 维度 | 验收含义 |
| --- | --- |
| 情节有效 | 本章发生真实变化，不是人物只在执行任务和交换信息 |
| 内容丰满 | 场景有过程、阻力、反应和余波，不像大纲或历史资料 |
| 人物鲜活 | 主要人物有独立欲望、判断和行动，对同一事件反应不同 |
| 对话可信 | 符合身份、关系和情绪，有停顿、回避、误解或潜台词 |
| 情绪自然 | 通过处境、行为和思绪表达，减少模板身体反应 |
| 连贯一致 | 时间、位置、能力、关系和动机与 Canon 一致 |
| 节奏顺畅 | 有张弛和场景层次，不连续堆事件，也不无意义注水 |
| 风格稳定 | 符合本书契约，但不机械模仿示例句式 |
| AI 味较淡 | 减少总结腔、说明书腔、套话排比、同义反复和刻意金句 |
| 阅读动力 | 读者关心人物或事件后续，不依赖每章强行钩子 |

审核报告必须给出具体段落、问题原因和可执行建议，不能只给抽象分数。

### 11.3 硬阻断与软建议

软建议不阻止定稿：

- 语言偏干；
- 场景不够丰满；
- 对话较机械；
- 人物区分度不足；
- 风格偏移；
- AI 味明显；
- 节奏或阅读动力不足。

硬阻断包括：

- Canon、时间线或人物状态存在无法解释的真实冲突；
- 候选正文为空或存在可证明的技术性截断状态；
- 候选 hash、章节会话或规划 revision 已变化；
- 复制检查命中大段逐字或近似逐字复现的本地语料、参考原文；
- 必要的复制检查或事务前置检查未完成。

情节相似、通用题材套路、表达风格接近或少量普通短语相同不构成复制阻断。

“正文不完整”的硬判断仅限可证明状态：正文为空、流式 attempt 尚未完成、Provider 明确报告 token limit 或截断、内容 hash/长度与 completed 元数据不一致。叙事上结尾突然或情节尚未展开属于软建议。

质量模型调用失败时记录 `quality_not_completed`，不剥夺作者定稿权。确定性复制检查、revision/hash 校验和 Canon conflict engine 必须完成。V1 复制硬检查只覆盖项目冻结或本地导入语料，以及本次明确检索且可复现的来源；没有可靠证据的“全网相似”只能作为软提示。

## 12. 原子定稿

### 12.1 准备阶段

定稿只能从一个已保存候选开始。

系统先固定：

- project、chapter session 和 candidate ID；
- candidate content hash；
- Canon revision；
- 故事块和未来计划 revision；
- 创作契约、圣经和模型绑定 revision；
- 质量审核结果 hash；
- 幂等键和 manifest hash。

`extraction` 模型只读取一次候选正文和必要上下文，生成完整 `FinalizationChangeSet`，至少包含：

- 章节标题和章节摘要；
- 新增、变化和失效的 Canon 事实；
- 人物当前状态和人物弧光进展；
- 关系、地点、势力、物品和规则变化；
- 新伏笔、已回收伏笔和未完成情节；
- 故事块、阶段和情节任务进度；
- 已发生的 `storyProgressEvents`；
- 作者确认后可以应用的 `planningPatches`；
- 仅供参考、不会自动写入的 `planningSuggestions`；
- 每项变化的正文证据位置和置信说明。

设定库、记忆、人物弧光和伏笔不得分别再次调用模型。

ChangeSet 是持久化实体，状态为：

```text
preparing → awaiting_author → committing → committed
                         ↘ invalidated | cancelled | failed
```

每章最多一个活动 ChangeSet。准备命令的幂等指纹绑定 candidate hash、Canon revision、Planning revision、模型绑定和上下文 manifest。已经成功持久化的提取结果不因刷新或网络断开再次调用模型。确认前任一基线 revision 漂移都会使 ChangeSet 进入 `invalidated`，不得自动提交；重新准备是一个明确的新 attempt。每个成功的 preparation attempt 只生成一个完整 ChangeSet。

提取输出必须通过闭合 schema 校验。`CanonConflictEngine` 再以确定性规则比较 ChangeSet 和当前 Canon；质量审核不得通过另一轮事实提取来判断冲突。

### 12.2 作者一次确认

定稿页面汇总展示：

- 原候选正文；
- 质量报告；
- 所有 Canon 变化；
- 所有状态视图变化；
- 故事块与未来计划变化；
- 硬阻断和软建议。

作者可以把候选载入为工作稿，修改后保存为新候选；也可以在整体确认前修正模型提取错误。修正保留审计轨迹，并重新执行 schema 和确定性 Canon 冲突校验，但不再次调用 extraction 模型。最终动作仍是一次确认整个变更集，不变成逐条勾选流程。

每次人工修正产生不可变 ChangeSet revision，并递增 `changeSetRevision`、重新计算 `changeSetContentHash`。确认命令必须携带 `expectedChangeSetRevision` 和 `expectedChangeSetHash`，定稿事务锁定并校验作者最终看到的确切版本。

### 12.3 单事务提交

作者确认后，后端不得再调用 Provider，并在一个数据库事务中：

1. 锁定项目、章节会话、候选、Canon 和相关规划；
2. 重新验证全部 revision、hash、manifest 和幂等键；
3. 写入不可变定稿章节；
4. 写入已批准 Canon 事件；
5. 根据同一个变更集生成并写入各派生视图 revision；
6. 由 Canon event 投影实际故事块进度，并应用作者确认的 future Planning patch；
7. 关闭当前章节会话；
8. 将项目推进到下一章可开始状态；
9. 写入 `FinalizationRecord`、请求指纹、幂等结果摘要，并将 ChangeSet 状态改为 `committed`；
10. 提交事务。

任何一步失败都完整回滚。候选保持原样，可安全重试。定稿成功后，正文和对应历史 Canon 只读。

同一幂等键和同一请求指纹返回首次提交结果；同键不同指纹返回冲突。`FinalizationRecord`、幂等结果和 ChangeSet 最终状态必须与正文、Canon 和 Projection 在同一事务中提交，不能在事务外补写。

项目备份、小说下载、前端刷新或网络断开都不能把“部分定稿”暴露为成功状态。结果未知时先按幂等键查询命令结果，不能盲目再次提交。

## 13. 最小流程门槛

只保留下列硬门槛，并将“可以进入查看”和“可以执行写操作”分开：

| 状态 | 仍可进入 | 被阻止的操作 |
| --- | --- | --- |
| 未选种子 | 选题与种子、其他只读模块 | 进入契约、规划写入、AI 写作 |
| 契约未确认 | 契约及只读模块 | 圣经生成、正式规划、AI 写作 |
| 圣经未确认 | 圣经、项目中心、写作台说明页 | 正式规划写入、正文生成 |
| 无分卷或故事块 | 所有规划模块和写作台 | 由唯一主动作补齐规划后才能生成 |
| 小纲未确认 | 写作台 | 正文生成 |
| Canon 与 Projection 不同步 | 全部只读查看 | Session 创建、AI 写入、候选冻结、定稿 |
| Provider 或绑定不可用 | 手工编辑、查看、下载、备份 | 需要对应模型的 AI 操作 |
| 自动暂存失败 | 当前写作台 | 长操作、候选冻结和危险离开 |
| AI 写入或定稿中 | 当前写作台只读 | 其他状态写入、章节切换和危险离开 |
| 无已保存候选 | 写作、候选保存 | 审查并定稿 |
| 已定稿章节 | 历史查看和下载 | 修改正文或历史 Canon |

Canon 与 Projection 同步不仅是 UI 门槛。创建 Session、AI 写入、候选冻结和定稿的后端服务都必须验证相同的 Canon/projection revision。不同步时提供“重建状态视图”恢复动作；重建只从 Canon 生成 Projection，不调用模型、不修改 Canon。

圣经确认后允许进入所有规划模块。没有分卷或故事块时仍允许进入写作台，由唯一主动作引导补齐下一项，而不是只展示无解释的禁用按钮。

所有说明遮罩都必须显示唯一的恢复动作，例如“去选择种子”“去确认圣经”或“重建状态视图”，不能只盖住内容。只读遮罩允许滚动和复制；操作遮罩是否允许导航由上表决定。组件设置 `aria-busy`，状态变化通过可访问的 live region 播报，键盘焦点在操作前后保持在可预测位置。

## 14. 提示、弹窗与错误恢复

统一反馈体系：

- 成功和普通提醒：右上角自动消失的 Toast；
- 表单错误：显示在对应字段旁，并聚焦首个错误；
- AI、网络和可恢复请求错误：显示在当前操作区域，保留输入并提供重试；
- 后端离线：全局持久横幅；
- 需要作者做选择：普通应用内弹窗；
- 永久删除和清除密钥：红色危险确认；
- AI 写入和定稿状态：统一只读遮罩，不额外弹阻塞框。

错误信息使用稳定公共错误码和中文恢复动作。可以显示 correlation ID 供排查，但不得展示 SQL、堆栈、请求头、Provider 原始响应或秘密。

常见恢复动作：

| 情况 | 恢复方式 |
| --- | --- |
| revision 冲突 | 重新加载最新工作稿，并保留本地未暂存内容供对比 |
| Provider 不可用 | 直达项目模型设置或全局 Provider 设置 |
| AI 生成失败 | 保留旧稿、作者要求和中断输出，允许重试 |
| 自动暂存失败 | 持久提示，禁止危险离开，允许复制当前正文 |
| 定稿结果未知 | 按幂等键核对结果，再决定重试 |
| 项目不存在或已归档 | 返回项目库为主动作，重试为次动作 |

## 15. 下载、备份、导入与归档

小说下载、项目备份和项目导入都使用统一耗时操作遮罩，显示操作名称和阶段，阻止重复提交。大文件生成期间禁止离开会使结果归属不清的页面；只有服务端明确支持安全取消时，下载和备份才显示“取消”。导入进入原子发布阶段后不可取消，只能查询结果。

### 15.1 下载小说

小说下载只包含已定稿章节，永远不回退到工作稿、候选稿或 `[暂无内容]` 占位。

第一版支持：

- 全书、按卷、按章；
- UTF-8 TXT；
- Markdown。

没有定稿章节时按钮禁用并明确说明原因。下载不需要确认。

### 15.2 项目备份

项目备份是可恢复的完整项目包，包含：

- manifest 版本和 hash；
- 项目、种子、契约和圣经 revision；
- 分卷、故事块、ChapterOutline 和未来计划；
- ChapterSession、定稿章节、WorkingDraft、WorkingDraftRevision、Candidate 和修订历史；
- 质量审核记录、持久化 FinalizationChangeSet 和安全 operation manifest；
- Canon 事件；
- 仅用于导入校验的派生视图 hash 快照；
- 项目冻结的风格、经验卡和完整语料版本；
- Provider 公共身份和模型名历史快照；
- 结果核对需要的历史幂等指纹，但不恢复为可再次执行的活动命令。

备份永不包含 API Key、Base URL、Authorization、Token、Password、DSN 或本机绝对路径。

开始备份时：

1. 若存在 AI lease 或正在提交的原子定稿，暂不允许备份并显示当前操作；
2. 停止 debounce，flush 自动暂存；
3. 暂存失败则终止备份；
4. 后端在一致性快照中导出所有稳定实体；
5. 已中断且仍在保留期内的 operation attempt 可以作为不可执行的恢复记录导出，活动 attempt 不得伪装为完成。

项目包内使用不可变 package-local logical ID 表达引用关系。导入为新项目时，数据库 ID 全部重新分配并建立映射；正文、候选、Canon payload 等基于内容字节的 hash 保持不变，包含实体 ID 的聚合 manifest 重新计算，并记录 `sourcePackageHash`。旧幂等键只作为历史证据导入到新的命名空间，不能触发或核对本机旧命令。

Provider 公共快照只用于说明历史生成来源，不按名称自动匹配或启用本机 Provider。重新绑定必须由作者显式选择。

当前版本只提供项目级完整备份，不恢复旧版全数据库 BackupReminder。未被任何项目冻结的全局语料和本机应用配置不包含在项目包中。

### 15.3 导入备份

导入先执行版本、大小、manifest hash、敏感字段和结构完整性预检。预检页面明确展示：

- 将导入的项目名称和数据数量；
- 被拒绝的敏感字段名称；
- 需要重新配置的 Provider；
- 导入后的新项目名称。

当前和旧备份只要包含秘密字段就一律拒绝，不做兼容剥离，也不回显字段值。导入包禁止绝对路径、`..` 路径穿越、符号链接和超出限制的压缩比例；每个条目分别校验声明大小、实际大小和 hash，敏感字段扫描递归覆盖 manifest、元数据、错误记录和嵌套文件。

点击“开始导入”即提交，不再增加第二次确认。导入始终创建新项目，不静默覆盖现有项目。导入后从 Canon 重建派生视图，再与包内校验 hash 比对；派生视图快照不是权威恢复源。模型绑定为 Not Ready，直到作者在本机显式选择有效 Provider。

不恢复旧 `includeApiKeys` 或任何旧格式兼容逻辑。

导入命令使用 `commandId`、幂等键和请求指纹。后端先把新 ID 映射和全部实体写入不可见 staging，完成 Canon/Projection 重建和 hash 校验后再原子发布为可见项目；任一步失败都完整清理 staging。同一幂等键和指纹返回同一导入项目，同键不同指纹冲突。网络结果未知时先按 `commandId` 查询，不能再次创建副本。

### 15.4 归档

归档只是从活动项目库隐藏：

- 归档：先 flush 自动暂存；存在 AI lease 或定稿提交时由当前操作遮罩阻止；暂存失败时不执行；成功后直接归档并提供撤销；
- 恢复：直接执行；
- 永久删除：只允许在已归档项目中执行，一次危险确认。

归档保留活动 ChapterSession、WorkingDraft 和候选。归档项目路由立即切换为只读归档状态；恢复后可以继续原工作稿。

`archived` 是所有后端写服务的统一前置条件。归档事务提交后，自动暂存、规划、AI、候选、ChangeSet 和定稿写入全部拒绝；旧标签页收到归档状态后保留尚未提交的本地正文供作者复制或在恢复项目后重新暂存，不能继续写入归档项目。

下载、备份和归档是三种不同能力，不得用一个模糊的“导出项目”替代。

## 16. 后端边界与数据一致性

正式能力拆成以下职责清晰的服务：

| 服务 | 职责 |
| --- | --- |
| ProjectLifecycleService | 项目创建、模型继承、归档、恢复、永久删除 |
| MarketSourceService | 来源适配、手动/计划刷新和安全采集边界 |
| MarketSnapshotService | 榜单快照、来源时间、规范化趋势视图和失败降级 |
| CreativeAssetService | 风格、经验卡、语料浏览、导入和冻结引用 |
| CreationContractService | 种子、发动机、契约和圣经 revision |
| PlanningService | 分卷、情节、故事块和章节小纲 |
| ContextAssemblyService | 按预算构建本章上下文 manifest |
| ChapterSessionService | 当前章会话和单一 WorkingDraft |
| DraftOperationService | 生成、改写、扩写、压缩、融合和流式尝试 |
| CandidateService | 候选原子冻结、加载和对比元数据 |
| QualityAuditService | 质量诊断、复制检查和技术前置检查，不提取事实 |
| CanonConflictEngine | 在 ChangeSet 生成后执行唯一的确定性 Canon 冲突校验 |
| FinalizationService | ChangeSet、一次确认和原子定稿 |
| CanonProjectionService | 以 Canon 事件重建只读视图 |
| ProjectPackageService | 小说下载、项目备份、预检和导入 |

前端 Store 按这些领域边界拆分，不再由一个巨型 `writerStore` 或 `WriterView` 同时承担请求、事务编排、编辑器状态、弹窗和导航。

启动应用时不执行历史 `ensure_schema` 大量 DDL。Schema 建立和重置必须通过明确的初始化或迁移命令完成；正常启动只验证 schema version 和必要能力。

## 17. 本地运行与安全边界

当前版本只允许本机单用户访问：

- 默认只绑定 `127.0.0.1`；
- 不实现公网匿名访问；
- 不因为“单用户”而允许秘密进入前端持久状态、任何响应或可观察日志；作者录入时只允许按第 5.2 节短暂经过受控表单和请求体；
- MySQL 8 是正式产品数据库；
- 真实浏览器测试产生的文章保留在产品数据库中，作者可以直接打开页面阅读。

未来如部署服务器并允许公网访问，必须作为独立版本增加身份认证、授权、TLS、CSRF、限流、审计和部署配置；不在当前本机版本中预埋半成品兼容分支。

## 18. 数据重置与旧代码处置

产品数据库仍是开发测试数据，可以按新 schema 重建，不做旧版本数据迁移。重置时仅保留已确认的样板项目身份和三个种子作为开发基准，其余派生测试数据清除。

按纵向功能替换完成后删除：

- 旧 `WriterView.vue` 和未再使用的旧 writer components；
- 旧 `writerStore`、旧前端 finalization commands 和旧直接字符串替换逻辑；
- 浏览器直连 Provider 的 AI client；
- 逐条 Canon 确认与定稿后补处理流程；
- 旧经验卡 localStorage、激活、审核和上架流程；
- 旧 full export/import 和 `includeApiKeys`；
- 不可达旧选题雷达、重复导出入口和重复导航；
- 仅靠源码正则断言行为的临时 contract tests；
- 启动时运行 DDL 的兼容代码；
- 已被冻结的 phase-e shadow QA 链路。

历史证据文件可以保留在 Git 历史或归档目录，但不得成为当前运行时依赖或产品事实来源。永久删除旧 worktree 和外部临时产物仍需单独执行清理范围核对。

## 19. 测试与验收

### 19.1 测试层级

1. **单元测试**：纯数据模型、状态派生、字数统计、hash、manifest、上下文预算和错误映射；
2. **前端组件测试**：主动作切换、遮罩、自动暂存、流式跟随、候选冻结和离开保护；
3. **后端服务测试**：幂等、revision、单活动命令、Provider 安全摘要和原子定稿；
4. **Disposable MySQL 8 集成测试**：事务回滚、锁、并发、导入预检和派生视图重建；
5. **正式产品 MySQL 8 浏览器验收**：真实页面、真实 Provider、真实数据库；
6. **作者内容验收**：直接阅读产品数据库中的真实生成文章。

Fake Provider 和 fake adapter 只能证明单元行为，不能授予 Provider Ready、DB Ready、浏览器 Ready 或产品内容 Ready。

### 19.2 浏览器自由操作验收

浏览器验收不能只执行固定脚本。除自动化主路径外，还要进行自由探索：

- 刷新每个模块并验证 URL 状态恢复；
- 在自动暂存、生成、改写和定稿中尝试导航和重复点击；
- 在流式输出时滚动、暂停跟随并回到最新；
- 故意制造网络失败、revision 冲突和 Provider 不可用；
- 编辑后直接保存候选，确认冻结的就是屏幕可见正文；
- 重新生成新稿，确认旧工作稿可恢复；
- 对比、融合并重新载入候选；
- 定稿任一步失败，确认章节、Canon、故事块全部回滚；
- 下载只包含定稿正文；
- 备份导入为新项目，且必须重新配置 Provider；
- 检查全部网络响应和错误页面无明文秘密；
- 归档、撤销、恢复和永久删除语义一致。

### 19.3 《典镇山河》内容验收

完整写作系统宣告可用前，使用《典镇山河》逐章手动生成、审查并定稿前 30 章。每章按第 11 节十项质量维度检查。

验收重点不是文笔是否高级，而是：

- 是否愿意继续读；
- 情节是否丰满而非只剩骨架；
- 人物是否有鲜明声音、欲望和关系；
- 对话是否像人物在交流而非模型在解释；
- 情绪是否来自场景而非模板动作；
- AI 味和机械味是否淡；
- 未完成情节能否自然跨章；
- Canon、人物状态、记忆、弧光和故事块是否始终一致；
- 原稿、工作稿、候选和定稿是否完整保留；
- 失败是否完整回滚。

测试文章保留在正式产品 MySQL 8 中，作者可以在网页中随时查看。自动化检查不能代替作者的最终内容判断。

## 20. 实施顺序

按可独立验收的纵向闭环实施：

1. **产品壳层与项目生命周期**：全局导航、项目库、项目中心、创建、编辑名称、归档、撤销、恢复、永久删除、路由恢复、Toast、弹窗和遮罩；
2. **创作准备**：创作资产、Provider/模型设置、市场来源、选题与种子、契约、圣经、模型继承和资产冻结；
3. **故事规划**：分卷、情节、故事块、小纲、已发生事实与未来计划；
4. **写作闭环**：自动暂存、流式新稿、改写、扩写、压缩、候选、对比和融合；
5. **原子定稿**：质量审核、一次提取、整体确认、单事务提交和失败回滚；
6. **项目包与下载**：小说下载、安全备份、预检和导入；
7. **真实验收**：本机 MySQL 8、真实 Provider、真实浏览器自由测试和《典镇山河》内容验收。

每一阶段完成后执行代码审计、自动测试和浏览器交互验收。不得先搭建另一套影子 QA 链路再声称产品能力已经完成。

尚未实现到对应阶段的入口不提前显示为可点击死按钮。第一阶段只交付真实可用的项目生命周期；小说下载、项目备份和导入入口在第六阶段随完整服务一起出现。

本文件是产品主规格，不对应一个不可审查的超大开发提交。七个阶段分别形成独立实施计划、独立分支或 worktree、独立测试证据和合并检查；前一阶段的公开契约稳定后再开始依赖它的下一阶段。

## 21. 完成定义

只有同时满足以下条件，才能宣布本轮产品重构完成：

- 正式路由只指向新产品链，旧链路不再可达；
- 项目从创建、种子、契约、圣经、规划、写作到定稿可以在真实 UI 中完成；
- 工作稿自动暂存、候选冻结、流式输出和失败恢复没有丢稿风险；
- 每个定稿准备 attempt 只执行一次结构化事实提取，并原子更新 Canon 和所有派生视图；
- 小说下载、项目备份、导入、归档和恢复可用；
