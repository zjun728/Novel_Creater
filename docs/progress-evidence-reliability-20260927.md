1. 提取上下文保留正文、已确认 Canon、规划任务与完成标准及小纲绑定身份；不再把小纲场景扩写、创作圣经未来剧情和合同内容提供给事实提取。审稿仍使用完整上下文，服务端原权威快照与漂移校验保持。
2. 新模型输出中的每条进度须带临时 `completionBasis`：实际发生/仅有安排/尚不确定、缺失要求、引用段落。completed 与 planned/uncertain 或非空缺项相矛盾时拒绝结果。该字段只在网关校验，不进入持久化 ChangeSet；旧报告读回、作者修改与数据库契约不变。
3. 存在场景任务进度时，使用同一绑定模型新增一次聚焦进度的复核。输入只给任务身份、权威任务标准和正文，不给第一次提取的结论与理由；复核不能新增事件或把原 started/advanced 升级为 completed。缺项、重复/未知身份、非法形状、失败或取消均不发布未复核进度。
4. 复核明确区分执行结果和剧情效果：未来调令已下、压力已产生，不等于人员实际离开；但任务仅要求下令时，下令即可完成。正文后来明确跨到次日并发生执行，则可以完成。
5. 父阶段/故事块按权威层级检查自己的实际子任务。复核后仍有子任务未完成，则原 completed 父项降为 advanced；无关阶段的未完成任务不影响已经完成的阶段。不会自动把原 advanced 父项提升为 completed，原有定稿上下文与父子进度校验继续执行。
6. 对证据理由中明确引用的已存在段落，服务端计算包含全部引用的连续区间，再从原正文计算偏移与哈希。只扩到模型明确引用的段落，不补造事实；未知段落仍拒绝。结构化 supportingParagraphIds 也必须落在最终区间内。规范化只用于新模型响应，不改历史报告。

含场景任务进度的提取增加一次模型调用，因此增加耗时与调用成本；没有新增自动重试或每任务一调用。正文生成、持久模型配置、前端及数据库结构未改。
