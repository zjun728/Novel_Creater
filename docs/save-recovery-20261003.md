## 最小实现

沿用控制器的 `recoveryPending` 和 `run` 写入保护，新增修正恢复阶段，没有新恢复框架或后端接口：

| 结果 | 页面含义与恢复行为 |
|---|---|
| 本地版本／哈希不合法，尚未发出 POST | 拒绝提交，保留输入，原校验不变 |
| POST 明确 HTTP 4xx 拒绝（408 除外） | 显示修正未保存，保留作者草稿；不假装服务端已保存 |
| POST 已返回成功，但 GET 失败 | 显示“修正已被服务端接受，但最新状态读取失败”，保留编辑并显示“刷新核对修正” |
| POST 网络、超时、5xx 或响应无法解析 | 显示“修正保存结果尚未确认”，保留编辑，要求刷新核对；不称未保存 |
| 刷新 GET 仍失败 | 保留恢复阶段、提示和写入锁定，不再次 POST |
| 刷新 GET 成功 | 使用服务端审查版本与内容，解除恢复锁定；不会前端自增修订或自动重新提交 |

待核对阶段仍可查看本地修正，保存、确认、定稿等控制器写入被现有机制阻止。按钮仅重新读取审查，不调用撤销状态接口，也不重试 POST。既有撤销恢复继续使用其固定 attempt 与版本核对路径，按钮仍为“核对撤销结果”。

面板仅在同一 attempt、候选 ID／hash 及修订／hash 都相同时保留草稿和未完成字段；读回已保存的新版本时显示权威 payload。切换审查／候选或不同版本仍按既有行为更新，不把旧编辑套到新版本。未保存状态继续触发现有离开保护。迟到 POST 在上下文 reset 后不能重新锁住新章节或触发重读。
