## 主路径

选题中心 → 选题建议 → 创建作品并确认种子 → 创作契约 → 创作圣经 → 分卷规划 → 情节线 → 首个故事块 → 第一章小纲 → 正文 → 审查 → 定稿与同步 → 准备第二章。

后续按同一循环演示到第五章定稿、第六章小纲。第二章后切换故事块，第三章后跨卷；章节长度与分卷时点为压缩演示安排，不是实际长篇规划标准。

## 操作规则

- 首次创作基础由系统提出建议，作者逐步确认。后续不要求重复配置。
- 每章完成页明确已完成章节、当前故事块进度与“准备第 N 章”。
- 系统根据定稿证据判断是否继续当前故事块；完成后按整体规划展开下一故事块或下一卷。不能以生成成功代替实际完成。
- 作者临时要求可不填，系统自动承接小纲、契约、实际状态与未解线索。
- 默认阅读，主动修改进入草稿与前后对比；未确认的修改不影响正式依据。
- 同步失败时先恢复同步，不能使用旧状态直接准备下一章。
- 保持 Writer Core 单一权威，未来计划与已发生事实分离。

## 分支与验证

38 个原生可编辑画板。主按钮目标已逐页检查，文本边界检查无越界；关键页面已导出截图检查。分支包括首次模型配置、第一章生成失败重试、小纲修改及取消、定稿同步恢复、第四章后离开并从项目库继续第五章。

这是固定示例的流程原型，不是运行中的产品。没有调用模型、修改真实小说或验证后端能力。未覆盖所有侧栏模块的独立操作，也不模拟任意文字输入与任意进度持久化；项目库恢复分支使用第四章完成存档。尚未在真实浏览器中逐次点击验收 Figma 播放器，当前证据为节点跳转结构与截图。

实现前需按此路径逐项映射现有路由、状态和服务，确认缺失入口与自动承接能力，再安排代码修复。不得将原型跳转当作真实全流程验收通过。
