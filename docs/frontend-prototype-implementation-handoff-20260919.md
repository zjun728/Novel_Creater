## 项目是什么、为什么要调整

Novel Creator 是本地长篇小说 AI 辅助创作平台。系统承担选题建议、头脑风暴、规划、小纲、正文及连续性维护，作者负责方向、审阅、修改和定稿决定。希望支持长篇持续创作，但尚不能宣称长篇质量稳定性已经验收。

用户期待的完整路径：

类型选择 → 主动点击生成选题建议 → 市场参考采集与归纳 → 多个创作建议；也可直接进入 AI 讨论 → 保存选题方向／候选种子 → 创建项目 → 确认种子 → 创作契约 → 创作圣经 → 分卷／情节线／故事块 → 当前章小纲 → 正文 → 审稿／修改 → 作者定稿 → 同步进度 → 创建下一章。

之前大部分模块已有功能，但右侧页面主次不清、编辑入口过多、内部规划对象直接暴露给作者，导致用户不知道下一步该点击哪里。脚本能填值或直接导航，并不表示真实用户能完成流程。因此先反复讨论并确认了 Figma 原型，现在应进入实施，避免再次整体改版。

目标效果：作者每一阶段都能看到当前状态、主要内容及明确的下一步；新增／编辑／采用等写入操作有清晰入口；浏览、切页签、查看历史不会改变正文；本章完成后能通过界面自然进入下一章。

## 已确认的实施范围

### 共享导航与布局

- 全局导航保留选题中心、项目库、创作资产、设置。
- 项目导航顺序：工作台、项目概览、作品稿件、故事规划；创作基础、设定与连续性、项目设置可展开。聚合入口不能删除内部业务对象或越过准备条件。
- 工作台主内容区：卷章目录／正文编辑区／右侧工具。这里的内部左右区域不包括全局左侧导航。
- 右侧四页签：助手／审稿／参考／版本。章节主操作位置稳定；工具区收起控制归工具区。切换页签不改正文、章号或版本；保留页签、选中问题和阅读位置。
- 仅常规 PC；最新约定验收实际浏览器内容视口 1366×768 和 1440×900、100% 缩放。允许正文和工具区独立滚动，不靠缩小正文掩盖拥挤。不增加移动端、额外窄屏方案或专注模式。

### 小纲、正文和审稿

- 工作台内完成当前章创建、小纲、正文、审稿及定稿。未生成小纲时只提供生成；待确认时不作为正文依据；确认后可查阅／主动编辑；章定稿后只读。
- 小纲／正文改变后，旧审稿结果不能继续作为有效定稿依据。
- 作者补充要求可留空，已确认小纲及设定应自动带入。验收不能依赖临时填写额外约束来掩盖真实用户默认路径问题。
- 审稿问题定位、局部 AI 修改在审稿页签内完成，不强迫作者反复切换助手页签。
- “必须调整”以现有后端阻断规则为准；建议和可忽略项不能被前端擅自升级为阻断，也不能忽略真正阻断。
- 原文变化、证据缺失或范围失效时，不强行定位／替换：提示重新审稿或手动查找。原型的整段文本相等判断只是有限示例，真实实现须复用版本／哈希及范围契约。
- 字数继承创作契约的范围，是软约束；超长明显时提示由作者决定重生成或继续定稿。**不拆章**，不以固定演示字数替代真实统计。

### 版本与保护

- 已有候选稿支持列表；前端展示真实数量和当前正在使用的正文，不实现成只有一个历史槽位。
- NC6 两份保存稿仅用于展示多版本操作，不是生产数量上限，不照搬原型的固定变量／固定章数。
- 重生成前明确是否保留当前最新正文为待定稿。保留成功后才开始依赖保存的操作；保存失败不能丢失或覆盖当前稿和已有历史。
- 点击待定稿先与当前正文对比，明确确认才切换；沿用保存保护、只读与生成中限制。
- 停止／失败保留已收到内容；局部 AI 修改保留采用前预览与撤销能力。
- 定稿已保存而进度未同步时，正文仍锁定，不能重复定稿或提前创建下一章。恢复同步只在对应状态出现。
- 创建下一章以权威进度为依据，不能用前端自行递增章号绕过故事块／分卷交接。跨章清空当前章临时状态，历史查阅不覆盖正在创作章节。

### 其他范围

- 语料导入提升到语料库页头，单份语料详情／版本操作保留对应归属。
- 已有合理页面保留，不为追求完全换皮全部重写。
- 全文版本差异导航、新增搜索筛选维度、完整来源追溯先核实现有能力；缺失单列，不作为本轮默认新增承诺。
